# 常规

## NS2Bench 是什么？

一个放在桌上的 Nintendo Switch 2 测试台。它在电脑上显示主机的画面和声音，让你或 AI 代理按下主机的按键。你可以录制片段、读取屏幕文字，并运行可重复的测试。

## 适合谁用？

在真机上测试软件的开发者、想自动化重复检查的人、做无障碍实验的人，以及想让 AI 代理一边操作主机、自己一边观看的任何人。

## 会修改我的主机吗？

不会。NS2Bench 只做电视和有线手柄会做的事：接收 HDMI 信号，并通过 USB 按键。主机上不会安装任何东西。 它适用于任何开箱即用的 Switch 2，系统版本不限：无需越狱、无需改机，也无需自制软件。

## 主机会联网吗？

不会。NS2Bench 从不让主机访问互联网。采集和 USB 输入完全不需要网络。可选的主机网络只应答主机的连接测试，从不转发流量。参见[离线主机网络](#offline-console-network)。

## 免费吗？

免费。NS2Bench 是基于 GPL-3.0 许可证的免费开源软件。你可以使用、修改和分享。无论是否修改，分发时都要保留"NS2Bench, created by PhantomPtr"署名和许可证；分发修改版时，还要向接收者提供源代码并注明已修改（见 NOTICE）。如果觉得有用，可以[支持它](README.md#support)。

## 和任天堂有关系吗？

没有。NS2Bench 是独立项目。Nintendo Switch 是任天堂的商标。

# 安装

## 我需要什么？

一张用于视频和声音的采集卡（必需），如果想按键，还需要一个输入设备：

- 带 USB 设备端口的 Linux 开发板（Luckfox Pico Pro/Max、Raspberry Pi Zero 2 W、Pi 4/5），
- 或 Raspberry Pi Pico 加一个 3.3 V USB 转 UART 适配器，
- 或 CH9329 模块（仅键盘和鼠标）。

[安装指南](docs/setup/README.md)为每种方案提供了接线图和步骤。

## 电脑上需要安装什么？

- **macOS：** 无需安装；只要允许摄像头、麦克风和本地网络权限。想保存片段就运行 `brew install ffmpeg`。
- **Windows：** ffmpeg（`winget install Gyan.FFmpeg`），如果串口适配器需要，还要装 CH340/CP210x 驱动。
- **Linux：** ffmpeg（`.deb` 会自动安装）以及 `video` 和 `dialout` 用户组（`sudo usermod -aG video,dialout $USER`）。

参见[开始之前](docs/setup/README.md#before-you-start-your-computer)。

## 该选哪种输入设备？

如果想用全部按键，包括 C、GL 和 GR，请用 Linux 开发板：它的 Pro 模式会让主机看到一个真正的 Switch 2 Pro手柄。Pico 是最便宜的手柄方案（除 C、GL、GR 外的全部按键）。CH9329 只提供键盘和鼠标。你也可以先只看画面，以后再加输入设备。

## 需要底座吗？

主机需要输出 HDMI，通常就是靠底座。输入设备插在底座的一个 USB 口上。

## 没有输入设备能用吗？

能。在 设置 → 设备 中选择 **仅查看（无输入设备）**。你可以观看、收听、截图、保存片段和读取屏幕文字。

## 在哪里设置采集卡？

在主窗口右侧的 **视频** 面板中。它只列出你的采集卡支持的格式。

## 在哪里设置输入设备？

在 **设置 → 设备** 中。更改无需重启即可生效；旧连接会先松开所有按键。

## 应用能安装 Bridge、Pico 固件或网络助手吗？

可以，在 **设置 → 安装** 中。**刷写 Pico** 会把 Bridge 固件写入 Raspberry Pi Pico（插入时按住 BOOTSEL）。**安装到开发板** 会通过 SSH 在 Linux 开发板上安装或更新 Bridge（请先设置密钥登录）。**安装助手** 会在 macOS 或 Linux 上把离线网络助手作为服务运行。下载内容来自与应用匹配的发行版，使用前会经过校验。

## 怎么知道它正常工作？

顶栏的 **视频** 标签变绿并显示帧率；主机接受输入设备后，**Bridge** 标签也会变绿。顶栏的 **诊断** 会复制一份完整的状态摘要。

# 采集与声音

## 哪些采集卡可用？

任何 USB（UVC）HDMI 采集卡。目标是 1080p60。已测试：UGREEN 15389（MS2130），1080p60 和 1440p30。

## 能同时用 OBS 吗？

macOS 上可以：NS2Bench 与 OBS 共享采集卡，从不抢占。Windows 和 Linux 上，ffmpeg 通常需要独占采集卡，请关闭其他占用它的应用。

## 没有画面。

确认主机已放入底座并开机，HDMI 线插在采集卡的 **输入** 口，并且在视频面板中选中了正确的采集卡。macOS 上，在 系统设置 → 隐私与安全性 中为 NS2Bench 允许 **摄像头**。运行 **诊断** 查看详情。

## 没有声音。

点击顶栏的 **声音关闭** 打开声音。macOS 上，为 NS2Bench 允许 **麦克风**。如果有两张相同的采集卡，NS2Bench 会按 USB 位置把声音和画面配对。

## 采集占用多少 CPU？

macOS 上，1080p60 时约占单核的 12%（硬件 JPEG 和 H.264）。Linux 上，MJPEG 采集卡的数据直接透传，不重新编码。

# 输入设备

## Bridge 标签一直是红色。

- **Linux 开发板：** 确认开发板已通电，且能通过 设置 → 设备 中的地址访问，令牌文件与开发板的令牌一致。
- **Pico：** 检查串口，波特率应为 921600；TX 和 RX 必须交叉（适配器 TX → Pico GP1，适配器 RX → Pico GP0），并且要连接 GND。
- **CH9329：** 与模块的波特率一致（通常是 9600）。

然后确认输入设备插在主机的 USB 口上，且主机处于唤醒状态。

## 按键没反应。

Switch 2 要求一次按键至少持续约 50 ms。NS2Bench 每次按键至少保持 75 ms。如果 Bridge 是绿色但没有反应，主机可能在休眠或屏幕变暗：第一次按键只会唤醒它。

## 怎样使用 C、GL 和 GR？

GL 和 GR 是 Nintendo Switch 2 Pro手柄背面的两个按键；Joy-Con 2 没有。要使用它们（以及 C），请用 Linux 开发板，并在操作面板中选择 **主机识别为 → Pro手柄**。主机随后会看到一个 Switch 2 Pro手柄。否则 C 键用作 GameChat 快捷键。

## 能用我自己的手柄吗？

能。把它插到电脑上；NS2Bench 按按键位置映射（下方的面键是 B）。

## 能用键盘打字吗？

在操作面板中选择 **你的键盘发送 → 键盘和鼠标**。主机会看到一个真正的 USB 键盘。这需要 Linux 开发板、标准模式下的 Pico，或 CH9329。

## 主机休眠时会怎样？

由主机 USB 供电的开发板会断电，并在主机唤醒时重启。NS2Bench 会自动重新连接。Bridge 离线期间的按键会被丢弃，之后不会重放。

## NS2Bench 能把主机从休眠中唤醒吗？

暂时不能。Switch 2 没有网络唤醒（Wake-on-LAN），而由主机 USB 口供电的开发板会随主机一起断电（实测：进入睡眠模式约 7 秒后 Bridge 断开；唤醒主机后，开发板启动，NS2Bench 自动重连，约 30 秒内就绪）。目前在探索两种方式：给开发板单独供电（使用不会向主机反向供电的 USB 电源分线器），让它保持运行；或者 HDMI-CEC 的“与电视电源状态同步”，由 HDMI 端的 CEC 设备唤醒主机。在此之前，请用主机的电源键唤醒它。 唤醒主机后，开发板会自动启动，NS2Bench 会在约 30 秒内自行重新连接。

# 离线主机网络

## 需要网络吗？

不需要。采集和 USB 输入无需任何网络。主机网络只用于通过局域网与主机通信的工具。

## 怎样给主机一个不能上网的局域网？

把主机的以太网（底座网口或 USB 适配器）连接到 Mac 或 Linux 电脑上一个专用的以太网适配器，然后运行 `ns2bench-netd`。它会分配地址，并且只应答连接测试。也可以用一个屏蔽了互联网的路由器、VLAN 或 Wi-Fi 网络。参见[安装指南](docs/setup/README.md#optional-offline-console-network)。

## 能关闭互联网屏蔽吗？

不能。这不是一个设置项。NS2Bench 从不转发、NAT 或代理主机流量，也从不查询上游 DNS 服务器。

## 我用的是 Windows。

网络服务运行在 macOS 和 Linux 上。在 Windows 上，请把它运行在接管主机以太网口的 Linux 开发板或电脑上，并从网络选项卡控制它（[远程助手](docs/REFERENCE.md#remote-helper-windows-hosts)），或使用屏蔽了互联网的路由器。

# 代理与 API

## 哪些代理可用？

任何 MCP 客户端：Claude Code、Codex、opencode 等。设置 → API 与 MCP 中有可直接复制的配置。

## 能阻止代理吗？

能。操作面板中的 **阻止代理（仅手动）** 会立即停止代理输入。只有你本人在 NS2Bench 窗口中才能再次关闭它。

## API 在我的网络上安全吗？

引擎默认只监听 `127.0.0.1`。监听其他地址需要令牌。其他网站的网页无法向它发送命令。

## API 文档在哪里？

在 [docs/REFERENCE.md](docs/REFERENCE.md#agents-mcp-and-http-api) 中。

# 应用与更新

## 更新是怎么进行的？

应用每天检查 GitHub 发布，有更新时会提示。每次下载在安装前都会与发布的 SHA-256 校验。自动下载和安装默认关闭；可在 设置 → 更新 中开启。

## macOS 提示应用已损坏或无法检查。

应用还没有经过公证。运行一次 `xattr -dr com.apple.quarantine /Applications/NS2Bench.app`，然后打开它。

## Windows 提示已保护你的电脑。

选择 **更多信息 → 仍要运行**。安装程序目前还没有用付费证书签名。

## 更新后 macOS 又要求摄像头或麦克风权限。

从 0.0.3 起，每个 NS2Bench 版本都使用同一签名，macOS 只询问一次并记住，重启和更新后也不再询问。从 0.0.2 或更早版本更新时会最后再问一次。

## 怎样更改主题或语言？

设置 → 外观。顶栏的月亮按钮可在浅色和深色之间切换。

## 我的片段、截图和日志在哪里？

在 `~/.ns2bench/`：片段、测试报告，以及 `~/.ns2bench/logs` 中每天一个日志文件（保留 7 天）。截图保存在你的“下载”文件夹。不会上传到任何地方。

## NS2Bench 能通知我吗？

能。**设置 → 通知** 可开启桌面通知：Bridge 或画面断开、测试和片段完成、代理开始操控，或有更新可用时都会提醒。默认只在 NS2Bench 处于后台时显示。

## 怎样安装命令行工具？

**设置 → 安装 → 安装命令行工具** 会把 `ns2bench` 加到你的 PATH（macOS 可能会询问一次密码；Linux 的 `.deb` 已自带安装）。然后运行 `ns2bench --help`。API 和 MCP 能做的它都能做。

# 故障排除

## 怎样报告 bug？

点击顶栏的 **帮助**，再点 **保存错误报告**（包含日志、状态和一张截图的 zip；不含令牌），并附加到 [GitHub issue](https://github.com/phantomptr/ns2bench/issues/new/choose)。

## 日志颜色是什么意思？

蓝色行是正常活动，琥珀色行是可能自行恢复的警告，红色行需要你处理。对于 NS2Bench 能识别的问题，行下方的蓝色框会说明发生了什么、该怎么做。日志面板中的 **问题** 只显示警告和错误；**全部** 还会加入每次 API 调用等详细信息。

## doctor 是做什么的？

应用中的 **帮助 → 运行检查**（或 `ns2bench doctor`） 会检查视频、主机画面、OCR、Bridge、USB 状态、校准和网络隔离，并告诉你哪一部分出了问题、该怎么做。`--probe` 还会在 HOME菜单 上按 RIGHT 和 LEFT，端到端测试输入。
