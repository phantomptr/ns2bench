# 一般

## NS2Bench 是什麼？

一個放在桌上的 Nintendo Switch 2 測試台。它在電腦上顯示主機的畫面和聲音，讓你或 AI 代理按下主機的按鍵。你可以錄製片段、讀取螢幕文字，並執行可重複的測試。

## 適合誰用？

在實機上測試軟體的開發者、想自動化重複檢查的人、做無障礙實驗的人，以及想讓 AI 代理一邊操作主機、自己一邊觀看的任何人。

## 會修改我的主機嗎？

不會。NS2Bench 只做電視和有線控制器會做的事：接收 HDMI 訊號，並透過 USB 按鍵。主機上不會安裝任何東西。 它適用於任何開箱即用的 Switch 2，系統版本不限：不需越獄、改機或自製軟體。已越獄的主機同樣可用。

## 主機會連網嗎？

不會。NS2Bench 從不讓主機存取網際網路。擷取和 USB 輸入完全不需要網路。選用的主機網路只回應主機的連線測試，從不轉送流量。請參閱[離線主機網路](#offline-console-network)。

## 免費嗎？

免費。NS2Bench 是採用 GPL-3.0 授權的免費開源軟體。你可以使用、修改和分享。無論是否修改，散布時都要保留「NS2Bench, created by PhantomPtr」署名和授權；散布修改版時，還要向接收者提供原始碼並註明已修改（見 NOTICE）。如果覺得有用，可以[支持它](README.md#support)。

## 和任天堂有關係嗎？

沒有。NS2Bench 是獨立專案。Nintendo Switch 是任天堂的商標。

# 安裝

## 我需要什麼？

一張用於影像和聲音的擷取卡（必要），如果想按鍵，還需要一個輸入裝置：

- 具備 USB 裝置連接埠的 Linux 開發板（Luckfox Pico Pro/Max、Raspberry Pi Zero 2 W、Pi 4/5），
- 或 Raspberry Pi Pico 加上一個 3.3 V USB 轉 UART 轉接器，
- 或 CH9329 模組（僅鍵盤和滑鼠）。

[安裝指南](docs/setup/README.md)為每種方案提供了接線圖和步驟。

## 電腦上需要安裝什麼？

- **macOS：** 不用安裝；只要允許相機、麥克風和區域網路權限。想儲存片段就執行 `brew install ffmpeg`。
- **Windows：** ffmpeg（`winget install Gyan.FFmpeg`），如果序列轉接器需要，還要裝 CH340/CP210x 驅動程式。
- **Linux：** ffmpeg（`.deb` 會自動安裝）以及 `video` 和 `dialout` 群組（`sudo usermod -aG video,dialout $USER`）。

請參閱[開始之前](docs/setup/README.md#before-you-start-your-computer)。

## 該選哪種輸入裝置？

如果想用全部按鍵，包括 C、GL 和 GR，請用 Linux 開發板：它的 Pro 模式會讓主機看到一個真正的 Switch 2 Pro控制器。Pico 是最便宜的控制器方案（除 C、GL、GR 外的全部按鍵）。CH9329 只提供鍵盤和滑鼠。你也可以先只看畫面，之後再加輸入裝置。

## 需要底座嗎？

主機需要輸出 HDMI，通常就是靠底座。輸入裝置插在底座的一個 USB 連接埠上。

## 沒有輸入裝置能用嗎？

能。在 設定 → 裝置 中選擇 **僅檢視（無輸入裝置）**。你可以觀看、收聽、截圖、儲存片段和讀取螢幕文字。

## 在哪裡設定擷取卡？

在主視窗右側的 **影像** 面板中。它只列出你的擷取卡支援的格式。

## 在哪裡設定輸入裝置？

在 **設定 → 裝置** 中。變更無需重新啟動即可生效；舊連線會先放開所有按鍵。

## 應用程式能安裝 Bridge、Pico 韌體或網路助手嗎？

可以，在 **設定 → 安裝** 中。**燒錄 Pico** 會把 Bridge 韌體寫入 Raspberry Pi Pico（插入時按住 BOOTSEL）。**安裝到開發板** 會透過 SSH 在 Linux 開發板上安裝或更新 Bridge（請先設定金鑰登入）。**安裝助手** 會在 macOS 或 Linux 上把離線網路助手當作服務執行。下載內容來自與應用程式相符的版本，使用前會經過驗證。

## 怎麼知道它正常運作？

頂列的 **視訊** 標籤變綠並顯示影格率；主機接受輸入裝置後，**Bridge** 標籤也會變綠。頂列的 **診斷** 會複製一份完整的狀態摘要。

# 擷取與聲音

## 哪些擷取卡可用？

任何 USB（UVC）HDMI 擷取卡。目標是 1080p60。已測試：UGREEN 15389（MS2130），1080p60 和 1440p30。

在 Windows 上，Elgato 4K Pro 等內建（PCIe）擷取卡也可用，只要它們在 OBS 中顯示為 **Video Capture Device**。在 **影像 → 裝置** 中選擇擷取卡，在 **影像 → 聲音** 中選擇它的聲音（或讓聲音維持自動）。NS2Bench 會向擷取卡要求它支援的解析度和影格率。如果擷取卡仍然拒絕，NS2Bench 會像 OBS 一樣改用擷取卡本身的預設設定。如果顏色看起來泛白，請關閉主機上的 HDR，或在擷取卡隨附軟體中關閉 HDR 輸出。

## 能同時用 OBS 嗎？

macOS 上可以：NS2Bench 與 OBS 共用擷取卡，從不搶占。Windows 和 Linux 上，ffmpeg 通常需要獨占擷取卡，請關閉其他占用它的 App。

## 沒有畫面。

確認主機已放入底座並開機，HDMI 線插在擷取卡的 **輸入** 埠，並且在影像面板中選了正確的擷取卡。macOS 上，在 系統設定 → 隱私權與安全性 中為 NS2Bench 允許 **相機**。執行 **診斷** 查看詳情。

## 沒有聲音。

點擊頂列的 **聲音關閉** 開啟聲音。macOS 上，為 NS2Bench 允許 **麥克風**。如果有兩張相同的擷取卡，NS2Bench 會依 USB 位置把聲音和畫面配對。

## 擷取占用多少 CPU？

macOS 上，1080p60 時約占單核心的 12%（硬體 JPEG 和 H.264）。Linux 上，MJPEG 擷取卡的資料直接傳遞，不重新編碼。

# 輸入裝置

## Bridge 標籤一直是紅色。

- **Linux 開發板：** 確認開發板已通電，且能透過 設定 → 裝置 中的位址連線，權杖檔案與開發板的權杖一致。
- **Pico：** 檢查序列埠，鮑率應為 921600；TX 和 RX 必須交叉（轉接器 TX → Pico GP1，轉接器 RX → Pico GP0），並且要連接 GND。
- **CH9329：** 與模組的鮑率一致（通常是 9600）。

接著確認輸入裝置插在主機的 USB 連接埠上，且主機處於喚醒狀態。

## 按鍵沒反應。

Switch 2 要求一次按鍵至少持續約 50 ms。NS2Bench 每次按鍵至少維持 75 ms。如果 Bridge 是綠色但沒有反應，主機可能在睡眠或螢幕變暗：第一次按鍵只會喚醒它。

## 怎樣使用 C、GL 和 GR？

GL 和 GR 是 Nintendo Switch 2 Pro控制器背面的兩個按鍵；Joy-Con 2 沒有。要使用它們（以及 C），請用 Linux 開發板，並在操作面板中選擇 **主機識別為 → Pro控制器**。主機隨後會看到一個 Switch 2 Pro控制器。否則 C 鍵用作 GameChat 快捷鍵。

## 能用我自己的手把嗎？

能。把它插到電腦上；NS2Bench 依按鍵位置對應（下方的面板按鍵是 B）。

## 能用鍵盤打字嗎？

在操作面板中選擇 **你的鍵盤傳送 → 鍵盤和滑鼠**。主機會看到一個真正的 USB 鍵盤。這需要 Linux 開發板、標準模式下的 Pico，或 CH9329。

## 主機睡眠時會怎樣？

由主機 USB 供電的開發板會斷電，並在主機喚醒時重新啟動。NS2Bench 會自動重新連線。Bridge 離線期間的按鍵會被捨棄，之後不會重播。

## NS2Bench 能把主機從睡眠中喚醒嗎？

可以，但需要一點輔助。螢幕變暗時按任意鍵即可喚醒，NS2Bench 會自動完成。睡眠模式、當機或關機則需要以下方式之一，在 **設定 → 裝置 → 電源與喚醒** 中設定：

- **HDMI-CEC（不需機械裝置）：** 在底座和擷取卡之間的 HDMI 線上接一個 USB-CEC 轉接器（例如 Pulse-Eight），它會像電視一樣送出「開機」訊號。在主機上開啟 **系統設定 → 電視輸出 → 與電視電源狀態同步**，並在電腦上安裝 libcec（Mac 上用 `brew install libcec`）。它也能讓主機進入睡眠。
- **電源鍵指令：** 用於 SwitchBot 之類的按鍵機器人、Home Assistant webhook 或繼電器。這是從當機或關機中恢復的唯一方法。

之後，**喚醒主機**（在無畫面畫面、搜尋、API `POST /api/power`、`power` MCP 工具以及 `ns2bench power wake` 中）會先嘗試 CEC，再在你允許時嘗試電源鍵，最後嘗試按鍵。Switch 2 沒有網路喚醒（Wake-on-LAN），而由主機 USB 埠供電的開發板會在進入睡眠模式約 7 秒後斷電；主機喚醒時它會重新開機，NS2Bench 會在約 30 秒內自動重新連線。

# 離線主機網路

## 需要網路嗎？

不需要。擷取和 USB 輸入不需要任何網路。主機網路只用於透過區域網路與主機通訊的工具。

## 怎樣給主機一個不能上網的區域網路？

把主機的乙太網路（底座網路埠或 USB 轉接器）連接到 Mac 或 Linux 電腦上一個專用的乙太網路轉接器，然後執行 `ns2bench-netd`。它會分配位址，並且只回應連線測試。也可以用一個封鎖了網際網路的路由器、VLAN 或 Wi-Fi 網路。請參閱[安裝指南](docs/setup/README.md#optional-offline-console-network)。

## 能關閉網際網路封鎖嗎？

不能。這不是一個設定項目。NS2Bench 從不轉送、NAT 或代理主機流量，也從不查詢上游 DNS 伺服器。

## 我用的是 Windows。

網路服務在 macOS 和 Linux 上執行。在 Windows 上，請把它執行在接管主機乙太網路埠的 Linux 開發板或電腦上，並從網路分頁控制它（[遠端助手](docs/REFERENCE.md#remote-helper-windows-hosts)），或使用封鎖了網際網路的路由器。

# 代理與 API

## 哪些代理可用？

任何 MCP 用戶端：Claude Code、Codex、opencode 等。設定 → API 與 MCP 中有可直接複製的設定。

## 能阻止代理嗎？

能。操作面板中的 **封鎖代理（僅手動）** 會立即停止代理輸入。只有你本人在 NS2Bench 視窗中才能再次關閉它。

## API 在我的網路上安全嗎？

引擎預設只監聽 `127.0.0.1`。監聽其他位址需要權杖。其他網站的網頁無法向它傳送命令。

## API 文件在哪裡？

在 [docs/REFERENCE.md](docs/REFERENCE.md#agents-mcp-and-http-api) 中。

# App 與更新

## 更新是怎麼進行的？

App 每天檢查 GitHub 發行版本，有更新時會提示。每次下載在安裝前都會與發行版本的 SHA-256 核對。自動下載和安裝預設關閉；可在 設定 → 更新 中開啟。

## macOS 提示 App 已損毀或無法檢查。

App 還沒有經過公證。執行一次 `xattr -dr com.apple.quarantine /Applications/NS2Bench.app`，然後開啟它。

## Windows 提示已保護你的電腦。

選擇 **其他資訊 → 仍要執行**。安裝程式目前還沒有用付費憑證簽署。

## 更新後 macOS 又要求相機或麥克風權限。

從 0.0.3 起，每個 NS2Bench 版本都使用同一簽章，macOS 只詢問一次並記住，重新啟動和更新後也不再詢問。從 0.0.2 或更早版本更新時會最後再問一次。

## 怎樣變更主題或語言？

設定 → 外觀。頂列的月亮按鈕可在淺色和深色之間切換。

## 我的片段、截圖和記錄在哪裡？

在 `~/.ns2bench/`：片段、測試報告，以及 `~/.ns2bench/logs` 中每天一個記錄檔（保留 7 天）。截圖會存到你的「下載」資料夾。不會上傳到任何地方。

## NS2Bench 能通知我嗎？

能。**設定 → 通知** 可開啟桌面通知：Bridge 或畫面中斷、測試和片段完成、代理開始操控，或有更新可用時都會提醒。預設只在 NS2Bench 位於背景時顯示。

## 怎樣安裝命令列工具？

**設定 → 安裝 → 安裝命令列工具** 會把 `ns2bench` 加到你的 PATH（macOS 可能會詢問一次密碼；Linux 的 `.deb` 已內建安裝）。然後執行 `ns2bench --help`。API 和 MCP 能做的它都能做。

# 疑難排解

## 怎樣回報 bug？

點擊頂列的 **說明**，再點 **儲存錯誤報告**（包含記錄、狀態和一張截圖的 zip；不含權杖），並附加到 [GitHub issue](https://github.com/phantomptr/ns2bench/issues/new/choose)。

## 記錄的顏色代表什麼？

藍色行是正常活動，琥珀色行是可能自行恢復的警告，紅色行需要你處理。對於 NS2Bench 能辨識的問題，行下方的藍色方塊會說明發生了什麼、該怎麼做。記錄面板中的 **問題** 只顯示警告和錯誤；**全部** 還會加入每次 API 呼叫等詳細資訊。

## doctor 是做什麼的？

應用程式中的 **說明 → 執行檢查**（或 `ns2bench doctor`） 會檢查視訊、主機畫面、OCR、Bridge、USB 狀態、校準和網路隔離，並告訴你哪一部分出了問題、該怎麼做。`--probe` 還會在 HOME選單 上按 RIGHT 和 LEFT，端對端測試輸入。
