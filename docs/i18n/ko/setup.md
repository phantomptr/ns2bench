# NS2Bench 설정하기

NS2Bench를 사용하면 사용자나 AI 에이전트가 컴퓨터에서 Nintendo Switch 2를 보고, 듣고, 조작할 수 있습니다.
이 안내서에서는 연결 방법을 설명합니다.

![NS2Bench 설정 한눈에 보기](overview.svg)

모든 설정은 서로 독립적인 두 부분으로 이루어집니다.

- **눈(항상 필요):** 본체의 HDMI를 USB 캡처 카드에 연결합니다. 캡처 카드가 컴퓨터에 영상과 소리를 전달합니다.
- **손(선택):** 작은 입력 장치를 본체의 USB 포트에 꽂습니다. 컴퓨터가 이 장치에 명령을 보냅니다. 본체는 유선 컨트롤러, 키보드, 마우스로 인식합니다.

사람은 브라우저의 NS2Bench 페이지나 데스크톱 앱을 사용합니다. 에이전트는 같은 컴퓨터에서 HTTP API나 MCP(`127.0.0.1:7630`)를 사용합니다. 모두가 하나의 벤치를 함께 쓰며, 에이전트의 모든 동작을 실시간으로 볼 수 있습니다.

**본체는 오프라인 상태를 유지합니다.** NS2Bench는 본체에 인터넷 접속을 절대 제공하지 않습니다. 캡처와 USB 입력에는 네트워크가 전혀 필요 없습니다.

## 어떤 설정이 필요한가요?

| 가지고 있는 것 | 설정 | 설정의 입력 연결 |
|---|---|---|
| 캡처 카드만 있음 | [보기 전용](#view-only) | 보기 전용 |
| USB 장치 모드를 지원하는 Linux 보드(Luckfox Pico Pro/Max, Raspberry Pi Zero 2 W, Pi 4/5) | [Linux 보드](#linux-usb-gadget-board) | 네트워크 Bridge |
| Raspberry Pi Pico(RP2040)와 3.3 V USB-UART 어댑터 | [Pico](#raspberry-pi-pico) | 시리얼 Bridge |
| CH9329 모듈(키보드와 마우스 전용) | [CH9329](#ch9329-module) | CH9329 |
| 본체를 로컬 네트워크에도 연결하고 싶음(홈브루 도구) | [오프라인 네트워크](#optional-offline-console-network) | (네트워크 탭) |

잘 모르겠다면 **보기 전용**으로 시작하고 나중에 입력 장치를 추가하세요. 입력 설정은 앱을 다시 시작하지 않아도 바뀝니다.

C, GL, GR을 포함한 모든 컨트롤러 버튼을 쓰고 싶다면 Linux 보드를 사용하세요. 보드의 **Pro** 모드에서는 본체가 Switch 2 Pro 컨트롤러로 인식합니다. Pico와 보드의 표준 모드는 C, GL, GR을 제외한 모든 버튼을 지원합니다. CH9329에는 컨트롤러 기능이 전혀 없습니다.

## 시작하기 전에: 컴퓨터 준비

[최신 릴리스](https://github.com/phantomptr/ns2bench/releases/latest)에서 앱을 설치한 다음 아래를 진행하세요.

### macOS (14 이상)

- **추가로 설치할 것이 없습니다.** 캡처, 소리, 화면 텍스트 읽기가 앱에 내장되어 있습니다.
- 처음 실행할 때: macOS가 앱이 손상되었거나 확인할 수 없다고 하면 `xattr -dr com.apple.quarantine /Applications/NS2Bench.app`을 한 번 실행하세요.
- 요청이 나오면 **카메라**(화면), **마이크**(본체 소리), **로컬 네트워크**(입력 장치)를 허용하세요. 나중에 시스템 설정 → 개인정보 보호 및 보안에서 바꿀 수 있습니다.
- **클립**(클립 저장)에는 ffmpeg가 필요합니다: `brew install ffmpeg`.
- 시리얼 어댑터(Pico, CH9329)는 드라이버 없이 동작하며, `/dev/cu.usbserial-…` 또는 `/dev/cu.usbmodem…`으로 나타납니다.

### Windows 10/11

- **ffmpeg 설치**(캡처, 소리, 클립에 사용): `winget install Gyan.FFmpeg`을 실행한 다음 NS2Bench를 다시 시작하세요. NS2Bench는 Chocolatey나 Scoop으로 설치한 ffmpeg, 또는 `ns2bench-app.exe` 옆에 있는 `ffmpeg.exe`도 찾습니다.
- SmartScreen이 "Windows의 PC 보호"라고 표시할 수 있습니다: **추가 정보 → 실행**을 선택하세요.
- USB-UART 어댑터는 제조사 드라이버(CH340/CH341 또는 CP210x)가 필요할 수 있습니다. 포트는 장치 관리자에 `COM3` 같은 이름으로 나타납니다.
- 선택: 화면 텍스트 읽기를 위한 [Tesseract](https://github.com/UB-Mannheim/tesseract/wiki).
- 오프라인 본체 네트워크 서비스는 Windows에서 실행되지 않습니다: [Linux 도우미나 라우터](#optional-offline-console-network)를 사용하세요.

### Linux

- **ffmpeg:** `.deb`가 자동으로 설치합니다. AppImage를 쓰는 경우 직접 설치하세요(`sudo apt install ffmpeg`, `sudo dnf install ffmpeg`, `sudo pacman -S ffmpeg`).
- **권한:** 캡처 카드와 시리얼 포트를 소유한 그룹에 자신을 추가한 다음 로그아웃했다가 다시 로그인하세요:
  `sudo usermod -aG video,dialout $USER` (Arch: `video,uucp`).
- AppImage: `chmod +x NS2Bench-*.AppImage`. 실행되지 않으면 FUSE 2를 설치하세요(`sudo apt install libfuse2`).
- 선택: 화면 텍스트 읽기를 위해 `sudo apt install tesseract-ocr`.
- 시리얼 포트는 `/dev/ttyACM0`(Pico) 또는 `/dev/ttyUSB0`(대부분의 어댑터)으로 나타납니다.

## 캡처 카드(모든 설정 공통)

- USB **UVC** HDMI 캡처 카드라면 무엇이든 됩니다. 목표는 1080p60입니다. 테스트한 제품: UGREEN 15389 (MS2130).
- 본체 독의 **HDMI 출력**을 캡처 카드의 HDMI 입력에 연결합니다. 캡처 카드는 USB로 컴퓨터에 연결합니다.
- **비디오** 패널에서 캡처 카드, 해상도, 프레임 속도, 화질을 선택합니다. 카드가 지원하는 항목만 표시됩니다.
- **소리**도 캡처 카드에서 나옵니다. 별도의 오디오 케이블은 없습니다.
- **macOS:** 작은 내장 도우미가 캡처를 담당합니다. OBS와 카드를 함께 씁니다: OBS가 이미 카드를 사용 중이면 NS2Bench는 OBS의 형식을 그대로 쓰고 카드를 빼앗지 않습니다. 처음 실행할 때 **카메라**(화면), **마이크**(본체 소리), **로컬 네트워크**(Bridge)를 허용하세요.
- **Linux와 Windows:** NS2Bench는 `ffmpeg`를 사용합니다(먼저 설치하세요). 카드가 비어 있어야 할 수 있으니, 화면이 나오지 않으면 OBS나 카드를 사용 중인 다른 앱을 닫으세요.
- `ns2bench devices`를 실행하면 NS2Bench가 인식하는 캡처 카드 목록을 볼 수 있습니다.

## 보기 전용

![보기 전용: 캡처 카드만, 입력 장치 없음](view-only.svg)

가장 간단한 벤치입니다. 실시간으로 보기, 녹화, 원본 해상도 스크린샷, 화면 텍스트 읽기(OCR)를 할 수 있습니다. 에이전트도 볼 수 있지만, 아무도 버튼을 누를 수는 없습니다.

**준비물**

- 독에 꽂은 본체
- USB HDMI 캡처 카드(UVC)
- HDMI 케이블과 캡처 카드의 USB 케이블

**단계**

1. 독의 HDMI 출력을 캡처 카드에 연결합니다.
2. 캡처 카드를 컴퓨터에 꽂습니다.
3. NS2Bench를 시작하고 `http://127.0.0.1:7630`(또는 데스크톱 앱)을 엽니다.
4. **비디오** 패널에서 캡처 카드를 선택합니다.
5. **설정 → 장치**에서 **입력 연결**을 **보기 전용**으로 설정하고 **입력 연결 적용**을 클릭합니다.

**동작 확인**

- 상단 표시줄의 **비디오** 표시가 초록색으로 바뀌고 본체 화면이 나타납니다.
- **Bridge** 표시에는 *not configured*라고 나옵니다. 이 설정에서는 정상입니다.

**자주 있는 문제**

- *화면이 검은색:* 본체를 깨우세요. 본체가 독에 꽂혀 있고 독에 전원이 들어오는지 확인하세요. 다른 HDMI 케이블로 바꿔 보세요.
- *목록에 카드가 없음:* macOS에서는 카메라 접근을 허용하세요. Linux나 Windows에서는 카드를 사용 중인 앱을 닫으세요.
- *소리가 안 남:* macOS에서는 마이크 접근을 허용하세요. 카드가 오디오 소스로 선택되어 있는지 확인하세요.

## Linux USB 가젯 보드

![Linux 보드: 본체에는 USB, 컴퓨터에는 Ethernet](input-linux-board.svg)

작은 Linux 보드가 USB 장치인 척합니다. 보드에서는 **NS2Bench Bridge**(`ns2bench-board`)가 실행됩니다. 테스트를 마친 설정입니다(Luckfox Pico Pro/Max). 두 가지 컨트롤러 모드를 모두 지원합니다.

- **표준**(기본값): 본체는 HORI 스타일 유선 컨트롤러 + USB 키보드 + USB 마우스로 인식합니다.
- **Pro**: 본체는 C, GL, GR을 포함한 모든 버튼이 있는 Switch 2 Pro 컨트롤러로 인식합니다. 이 모드에서는 키보드와 마우스를 쓸 수 없습니다.

조작 패널의 **본체 인식**에서 모드를 바꿉니다. 약 8초가 걸립니다.

**준비물**

- USB 장치(OTG) 모드를 지원하는 Linux 보드: Luckfox Pico Pro/Max, Raspberry Pi Zero 2 W, 또는 USB-C 포트를 사용하는 Pi 4/5
- 보드의 **OTG** 포트에서 독의 USB 포트로 연결할 USB 케이블
- 컴퓨터에 연결할 Ethernet 케이블(또는 Wi-Fi나 보드의 USB 네트워크 사용)
- 위의 캡처 카드 설정

**단계**

1. 컴퓨터에서 보드에 NS2Bench Bridge를 설치합니다: `make board-install BOARD=<ssh-host>`. 64비트 Raspberry Pi라면 `BOARD_TARGET=aarch64-unknown-linux-musl`을 추가하세요.
2. 보드의 **OTG** USB 포트를 독의 USB 포트에 연결합니다.
3. 보드의 Ethernet을 컴퓨터에 연결합니다(또는 둘 다 같은 사설 네트워크에 연결합니다).
4. Bridge가 아직 실행 중이 아니면 시작합니다: `ssh <ssh-host> /opt/ns2bench/ns2bench-hidd.sh start --bind <board-ip>`.
5. 컴퓨터의 토큰 파일 `~/.ns2bench/hidd.token`이 보드의 토큰과 같은지 확인합니다.
6. **설정 → 장치**에서 다음과 같이 설정합니다.
   - **입력 연결:** 네트워크 Bridge
   - **Bridge 주소:** 보드의 IP(기본값 `192.168.79.2`)
   - **Bridge 포트:** `7631`
   - **Bridge 토큰 파일:** `~/.ns2bench/hidd.token`
7. **입력 연결 적용**을 클릭합니다.

**동작 확인**

- **Bridge** 표시가 초록색으로 바뀌고 왕복 시간과 *usb configured*가 표시됩니다.
- 화면의 Joy-Con에서 버튼을 눌러 보세요. 본체가 반응하고 버튼에 불이 들어옵니다.

**본체가 절전 모드일 때**

본체의 USB로 전원을 받는 보드는 본체가 절전 모드에 들어가면 전원이 꺼지고, 본체가 깨어나면 다시 부팅됩니다. NS2Bench를 계속 실행해 두세요: 약 3초 안에 이를 감지하고 스스로 다시 연결합니다. 보드 부팅이 끝나고 본체가 USB 설정을 마치면 입력이 다시 동작합니다.

이렇게 되려면 보드가 부팅 시 스스로 다시 시작해야 합니다. 보드에 `/opt/ns2bench/gadget.sh`를 실행한 뒤 `/opt/ns2bench/ns2bench-hidd.sh start`를 실행하는 부팅 스크립트를 추가하세요. 사용하는 보드와 독으로 실제 절전과 깨우기를 한 번 테스트하세요.

**자주 있는 문제**

- *Bridge offline · reconnecting:* 케이블과 보드의 IP를 확인하세요. 보드에 ping을 보내 보세요. 보드에서 Bridge가 실행 중인지 확인하세요.
- *Bridge는 연결됐지만 usb가 configured가 아님:* 본체를 깨우세요. 케이블이 전원 전용 포트가 아니라 보드의 **OTG** 포트에 꽂혀 있는지 확인하세요. 전원만 전달하는 케이블도 있습니다.
- *HOME 메뉴에서 마우스가 반응하지 않음:* 정상입니다. 본체는 마우스 입력을 읽지만, 커서를 표시하는 소프트웨어는 일부뿐입니다.
- *키보드가 무시됨:* 본체의 USB 키보드 지원은 설정 → 컨트롤러와 액세서리에 있습니다.
- 보드에서는 `ns2bench-hidd.sh`와 `gadget.sh`로만 중지하고 시작하세요. 패턴으로 프로세스를 종료하지 마세요.

## Raspberry Pi Pico

![Raspberry Pi Pico: 본체에는 USB, 컴퓨터의 USB 어댑터에는 UART](input-pico.svg)

NS2Bench Bridge 펌웨어를 실행하는 Raspberry Pi Pico(RP2040)입니다. USB 포트는 본체에 연결되며, 표준 모드의 Linux 보드와 같은 컨트롤러 + 키보드 + 마우스로 나타납니다. 컴퓨터는 별도의 USB-UART 어댑터를 통해 시리얼(UART) 링크로 Pico와 통신합니다.

> Pico 펌웨어는 빌드는 되었지만 아직 실제 하드웨어에서 실행해 보지 않았습니다. 사용 후기를 환영합니다.

**준비물**

- Raspberry Pi Pico(RP2040)와 micro-USB 케이블
- **3.3 V** USB-UART 어댑터(CP2102, FT232 또는 CH340)
- 점퍼 와이어 3개
- 위의 캡처 카드 설정

**단계**

1. 펌웨어를 빌드합니다: `make pico`. `firmware/pico/ns2bench-pico.uf2`가 만들어집니다.
2. **BOOTSEL** 버튼을 누른 채로 Pico를 **컴퓨터**에 꽂습니다. **RPI-RP2**라는 드라이브가 나타납니다.
3. `.uf2` 파일을 그 드라이브에 복사합니다. Pico가 다시 시작됩니다. 분리하세요.
4. Pico와 어댑터를 연결합니다.
   - Pico **GP0**(1번 핀, UART0 TX) → 어댑터 **RX**
   - Pico **GP1**(2번 핀, UART0 RX) ← 어댑터 **TX**
   - Pico **GND**(3번 핀) — 어댑터 **GND**
   - 어댑터의 3.3 V / 5 V 핀은 연결하지 마세요. Pico는 본체에서 전원을 받습니다.
5. Pico의 micro-USB를 독의 USB 포트에 꽂습니다.
6. 어댑터를 컴퓨터에 꽂습니다.
7. **설정 → 장치**에서 다음과 같이 설정합니다.
   - **입력 연결:** 시리얼 Bridge
   - **시리얼 포트:** 어댑터(예: macOS에서는 `/dev/cu.usbserial-XXXX`, Linux에서는 `/dev/ttyUSB0`, Windows에서는 `COM3`)
   - **전송 속도:** `921600`
8. **입력 연결 적용**을 클릭합니다.

선택: `NS2BENCH_TOKEN=... make pico`로 빌드하면 Pico가 토큰을 요구하게 됩니다(컴퓨터에도 같은 토큰 파일을 설정하세요). 어댑터가 921600을 지원하지 않으면 `NS2BENCH_BAUD=115200`으로 빌드하세요.

**동작 확인**

- **Bridge** 표시가 초록색으로 바뀌고 *usb configured*가 표시됩니다.
- 화면의 Joy-Con에서 누른 버튼이 본체에 전달됩니다.

**자주 있는 문제**

- *시리얼 포트가 나타나지 않음:* 어댑터 드라이버(CP210x, FTDI 또는 CH340)를 설치한 다음 다시 꽂으세요.
- *Bridge offline:* TX와 RX가 바뀌었을 가능성이 큽니다. TX는 항상 RX로 연결합니다. GND도 확인하세요.
- *응답이 깨지거나 없음:* 전송 속도가 펌웨어와 같아야 합니다(다른 값으로 빌드하지 않았다면 921600).
- *5 V 어댑터는 절대 사용하지 마세요.* Pico의 핀은 3.3 V 전용입니다.

## CH9329 모듈

![CH9329: 본체에는 USB, 컴퓨터에는 UART](input-ch9329.svg)

CH9329 모듈은 시리얼 명령을 USB 키보드와 마우스 입력으로 바꿉니다. 저렴하고 간단하지만 **컨트롤러 기능이 없습니다**: 버튼도 스틱도 없습니다. 입력과 포인팅 용도로만 사용하세요.

**준비물**

- CH9329 모듈
- 3.3 V USB-UART 어댑터(모듈 케이블에 USB-시리얼이 내장되어 있다면 필요 없음)
- 위의 캡처 카드 설정

**단계**

1. 모듈의 USB(HID) 쪽을 독의 USB 포트에 꽂습니다.
2. UART 쪽을 어댑터에 연결합니다: 모듈 TX → 어댑터 RX, 모듈 RX ← 어댑터 TX, GND — GND. (모듈에 USB-시리얼이 내장되어 있다면 건너뛰세요.)
3. 어댑터(또는 모듈의 시리얼 케이블)를 컴퓨터에 꽂습니다.
4. **설정 → 장치**에서 다음과 같이 설정합니다.
   - **입력 연결:** CH9329
   - **시리얼 포트:** 어댑터의 포트
   - **전송 속도:** 모듈의 설정값, 보통 `9600`
5. **입력 연결 적용**을 클릭합니다.

**동작 확인**

- **Bridge** 표시가 초록색으로 바뀝니다.
- 네이티브 키보드 모드에서 입력한 내용이 본체에 나타납니다(예: 텍스트 입력란).

**자주 있는 문제**

- *컨트롤러 버튼이 동작하지 않음:* 정상입니다. CH9329는 키보드와 마우스 전용입니다.
- *아무 반응이 없음:* 전송 속도를 확인하고, 필요하면 TX/RX를 바꿔 보세요.
- *본체가 키보드를 무시함:* 설정 → 컨트롤러와 액세서리 → USB 키보드를 확인하세요.

## 선택: 오프라인 본체 네트워크

![본체에 오프라인 네트워크를 제공하는 세 가지 방법](network.svg)

홈브루 로더 같은 로컬 네트워크 도구를 쓸 때만 필요합니다. 캡처와 입력에는 절대 필요하지 않습니다.

어떤 방식을 고르든 본체는 **인터넷에 연결되지 않습니다**. NS2Bench는 트래픽을 전달하지 않고, 인터넷 공유나 NAT, 프록시를 켜지 않으며, 외부 DNS 서버에 묻지 않습니다. 로컬 DNS는 본체의 연결 테스트에만 응답하고, 그 밖의 모든 이름은 거부합니다. 본체가 시도하는 모든 조회는 **network** 로그에 표시됩니다.

컴퓨터와 Linux 보드 사이의 Bridge 연결은 이와 별개입니다. 평소 쓰는 LAN을 사용해도 됩니다.

### A · 직접 케이블 연결(macOS 또는 Linux)

**준비물:** 컴퓨터에 본체 전용으로 쓸 여분의 Ethernet 어댑터, Ethernet 케이블, 그리고 독의 LAN 포트(또는 본체에 연결한 USB-Ethernet 어댑터).

1. 전용 어댑터에 고정 사설 주소를 지정합니다(예: `192.168.80.1/24`). NS2Bench는 인터페이스를 대신 설정해 주지 않습니다.
2. `bench.json`에 그 인터페이스를 적습니다(사용하는 어댑터의 인터페이스 이름을 쓰세요):
   ```json
   "network": { "interface": "en7", "address": "192.168.80.1", "subnet": "192.168.80.0/24",
                "pool_start": "192.168.80.10", "pool_end": "192.168.80.13" }
   ```
   네트워크 서비스를 빌드합니다: `make netd`.
3. 포트를 열지 않고 설정을 확인합니다: `native/target/release/ns2bench-netd --check bench.json`.
4. 서비스로 설치합니다.
   - **macOS:** 바이너리를 `~/.ns2bench/bin/ns2bench-netd`에 복사하고, `launchd/ns2bench-netd.plist.template`을 채운 뒤 `~/Library/LaunchAgents/`에 복사합니다. root 권한은 필요 없습니다.
   - **Linux:** `/opt/ns2bench/ns2bench-netd`에 설치하고 systemd 유닛 `launchd/ns2bench-netd.service`를 사용합니다.
5. 본체의 Ethernet을 전용 어댑터에 연결합니다.
6. **설정 → 네트워크**에서 **직접 연결, 격리된 컴퓨터 ↔ 본체**를 선택합니다. 필요에 따라 로컬 DHCP, DNS, 연결 테스트 페이지를 켠 다음 적용합니다.

본체는 풀에서 주소를 받습니다(예: `192.168.80.10`–`192.168.80.13`). **네트워크** 탭에서 실시간 상태와 임대 정보를 볼 수 있습니다.

IP 포워딩이 켜져 있거나 이를 확인할 수 없으면 서비스는 시작을 거부합니다. 의도된 동작입니다.

### B · 격리된 라우터, VLAN 또는 Wi-Fi(모든 OS)

1. 본체용 라우터, VLAN 또는 Wi-Fi 네트워크를 **IPv6를 포함해 인터넷을 차단한 상태로** 설정합니다. 일반 가정용 LAN은 격리되어 있지 않습니다.
2. 라우터가 주소를 나눠 주게 합니다(DHCP).
3. 본체를 Ethernet이나 Wi-Fi로 연결합니다.
4. **설정 → 네트워크**에서 **격리된 라우터 / VLAN / Wi-Fi**를 선택합니다. 그러면 라우터와 충돌하지 않도록 NS2Bench의 로컬 DHCP와 DNS가 꺼집니다.

### C · 원격 도우미를 쓰는 Windows 컴퓨터

Windows에서는 네트워크 서비스를 로컬로 실행할 수 없습니다. 대신 Linux 보드나 PC에서 실행하고 Windows에서 제어하세요.

1. Linux 도우미에서 방식 A처럼 `ns2bench-netd`를 설정합니다. 도우미가 본체의 Ethernet을 담당합니다.
2. 토큰을 만듭니다: `openssl rand -hex 16 > ~/.ns2bench/netd-control.token`. 같은 파일을 Windows 컴퓨터에 복사합니다.
3. 도우미 설정에 본체 네트워크에 **속하지 않는** 사설 주소로 관리용 리스너를 추가합니다:
   ```json
   "network": { "control": { "listen": "192.168.79.1:7632", "token_file": "~/.ns2bench/netd-control.token" } }
   ```
4. Windows의 NS2Bench 설정에서 도우미를 지정합니다:
   ```json
   "network": { "helper": { "url": "http://192.168.79.1:7632", "token_file": "~/.ns2bench/netd-control.token" } }
   ```
5. 관리용 연결은 사설로 유지하세요: 직접 케이블이나 보드의 USB 네트워크를 사용합니다. 트래픽은 암호화되지 않은 HTTP입니다.

그러면 Windows의 **네트워크** 탭에 도우미의 상태와 제어 항목이 표시됩니다. 또는 도우미 없이 방식 B를 사용하세요.

**자주 있는 문제**

- *네트워크 탭에 사용할 수 없다고 표시됨:* 서비스가 실행 중이 아니거나, 서비스와 UI가 서로 다른 상태 폴더를 쓰고 있습니다. Windows에서는 `network.helper`와 두 토큰 파일이 같은지 확인하세요.
- *본체가 주소를 받지 못함:* 설정의 인터페이스 이름과 서브넷, 그리고 케이블이 전용 어댑터에 연결되어 있는지 확인하세요.
- *본체가 인터넷에 연결되지 않았다고 함:* 정상입니다. 연결 테스트는 로컬에서 통과하지만 그 이상은 나가지 않습니다.

## 에이전트

표시가 모두 초록색이 되면 에이전트가 벤치를 사용할 수 있습니다. **설정 → API 및 MCP**를 열면 API 주소, 요청 예시, 그리고 Claude Code, Codex, opencode용으로 바로 복사할 수 있는 MCP 설정이 있습니다. 에이전트와 사람은 같은 조작을 공유하며, 수동 전용 스위치로 언제든 에이전트 입력을 막을 수 있습니다.

## Windows 참고 사항

- 캡처는 DirectShow와 함께 `ffmpeg`를 사용합니다. 카드를 사용 중인 다른 앱은 닫으세요.
- Linux 보드, Pico, CH9329 모두 Windows에서 동작합니다. 시리얼 포트 이름은 `COM3`, `COM4` 등입니다.
- Windows에는 로컬 네트워크 서비스가 없습니다. 원격 도우미(방식 C)나 격리된 라우터(방식 B)를 사용하세요.
