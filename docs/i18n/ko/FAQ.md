# 일반

## NS2Bench란?

책상 위의 Nintendo Switch 2를 위한 벤치입니다. 본체의 화면과 소리를 컴퓨터에 보여 주고, 사용자나 AI 에이전트가 버튼을 누를 수 있게 해 줍니다. 클립 녹화, 화면 속 텍스트 읽기, 반복 가능한 테스트 실행을 할 수 있습니다.

## 누구를 위한 것인가요?

실제 하드웨어에서 소프트웨어를 테스트하는 개발자, 반복적인 확인을 자동화하려는 사람, 접근성 실험을 하는 사람, 그리고 AI 에이전트가 본체를 조작하는 것을 지켜보고 싶은 모든 사람을 위한 것입니다.

## 본체를 개조하나요?

아니요. NS2Bench는 TV와 유선 컨트롤러가 하는 일만 합니다. HDMI를 받고 USB로 버튼을 누릅니다. 본체에는 아무것도 설치되지 않습니다. 상자에서 꺼낸 그대로의 Switch 2에서, 어떤 시스템 버전이든 작동합니다. 탈옥, 개조, 홈브루가 필요 없습니다. 탈옥한 본체에서도 작동합니다.

## 본체가 인터넷에 연결되나요?

아니요. NS2Bench는 본체에 인터넷 접속을 절대 제공하지 않습니다. 캡처와 USB 입력에는 네트워크가 전혀 필요 없습니다. 선택 사항인 본체 네트워크는 본체의 연결 테스트에만 응답하며 트래픽을 전달하지 않습니다. [오프라인 본체 네트워크](#offline-console-network)를 참고하세요.

## 무료인가요?

네. NS2Bench는 GPL-3.0 라이선스의 무료 오픈 소스입니다. 자유롭게 사용, 수정, 공유할 수 있습니다. 배포할 때는 수정 여부와 관계없이 "NS2Bench, created by PhantomPtr" 표기와 라이선스를 유지하고, 수정한 버전을 배포할 때는 받는 사람에게 소스 코드를 제공하고 수정본임을 표시해야 합니다(NOTICE 참고). 유용하다면 [후원](README.md#support)할 수 있습니다.

## 닌텐도와 관련이 있나요?

아니요. NS2Bench는 독립 프로젝트입니다. Nintendo Switch는 닌텐도의 상표입니다.

# 설정

## 무엇이 필요한가요?

영상과 소리를 위한 캡처 카드(항상 필요)와, 버튼을 누르려면 입력 장치 하나가 필요합니다.

- USB 디바이스 포트가 있는 Linux 보드(Luckfox Pico Pro/Max, Raspberry Pi Zero 2 W, Pi 4/5),
- 또는 Raspberry Pi Pico와 3.3 V USB-UART 어댑터,
- 또는 CH9329 모듈(키보드와 마우스만).

[설정 가이드](docs/setup/README.md)에 각각의 연결도와 단계가 있습니다.

## 컴퓨터에 무엇을 설치해야 하나요?

- **macOS:** 없습니다. 카메라, 마이크, 로컬 네트워크만 허용하세요. 클립을 저장하려면 `brew install ffmpeg`.
- **Windows:** ffmpeg(`winget install Gyan.FFmpeg`), 그리고 시리얼 어댑터에 필요하다면 CH340/CP210x 드라이버.
- **Linux:** ffmpeg(`.deb`가 설치함)와 `video`, `dialout` 그룹(`sudo usermod -aG video,dialout $USER`).

[시작하기 전에](docs/setup/README.md#before-you-start-your-computer)를 참고하세요.

## 어떤 입력 장치를 골라야 하나요?

C, GL, GR을 포함한 모든 버튼을 원한다면 Linux 보드를 사용하세요. Pro 모드에서는 본체에 진짜 Switch 2 Pro 컨트롤러로 보입니다. Pico는 가장 저렴한 컨트롤러 옵션입니다(C, GL, GR을 제외한 모든 버튼). CH9329는 키보드와 마우스만 제공합니다. 보기만으로 시작하고 나중에 입력 장치를 추가할 수도 있습니다.

## 독이 필요한가요?

본체가 HDMI를 출력할 방법이 필요한데, 보통은 독입니다. 입력 장치는 독의 USB 포트 중 하나에 꽂습니다.

## 입력 장치 없이 쓸 수 있나요?

네. 설정 → 장치에서 **보기 전용(입력 장치 없음)** 을 선택하세요. 화면 보기, 소리 듣기, 스크린샷, 클립 저장, 화면 속 텍스트 읽기를 할 수 있습니다.

## 캡처 카드는 어디서 설정하나요?

메인 창 오른쪽의 **비디오** 패널에서 설정합니다. 카드가 지원하는 형식만 표시됩니다.

## 입력 장치는 어디서 설정하나요?

**설정 → 장치** 에서 설정합니다. 변경 사항은 재시작 없이 적용되며, 이전 연결은 먼저 모든 버튼을 뗍니다.

## 앱에서 Bridge, Pico 펌웨어, 네트워크 도우미를 설치할 수 있나요?

네, **설정 → 설치** 에서 할 수 있습니다. **Pico 플래시** 는 Raspberry Pi Pico에 Bridge 펌웨어를 올립니다(꽂을 때 BOOTSEL을 누르고 있으세요). **보드에 설치** 는 SSH로 Linux 보드에 Bridge를 설치하거나 업데이트합니다(먼저 키 로그인을 설정하세요). **도우미 설치** 는 오프라인 네트워크 도우미를 macOS나 Linux에서 서비스로 실행합니다. 다운로드는 앱과 맞는 릴리스에서 받으며 사용 전에 검증됩니다.

## 작동하는지 어떻게 알 수 있나요?

상단 바의 **비디오** 표시가 프레임 레이트와 함께 초록색이 되고, 본체가 입력 장치를 받아들이면 **Bridge** 표시가 초록색이 됩니다. 상단 바의 **진단** 은 전체 상태 요약을 복사합니다.

# 캡처와 소리

## 어떤 캡처 카드가 작동하나요?

모든 USB(UVC) HDMI 캡처 카드가 작동합니다. 목표는 1080p60입니다. 테스트 완료: UGREEN 15389(MS2130), 1080p60 및 1440p30.

Windows에서는 Elgato 4K Pro 같은 내장(PCIe) 카드도 OBS에서 **Video Capture Device**로 표시되면 작동합니다. **비디오 → 장치**에서 카드를, **비디오 → 사운드**에서 그 소리를 고르세요(사운드는 자동으로 두어도 됩니다). NS2Bench는 카드가 지원하는 크기와 프레임 레이트를 요청합니다. 그래도 카드가 거부하면 OBS처럼 카드 자체의 기본 설정으로 되돌아갑니다. 색이 바래 보이면 본체의 HDR을 끄거나 카드 자체 소프트웨어의 HDR 출력을 끄세요.

## OBS를 동시에 쓸 수 있나요?

macOS에서는 가능합니다. NS2Bench는 OBS와 카드를 공유하며 절대 빼앗지 않습니다. Windows와 Linux에서는 보통 ffmpeg가 카드를 독점해야 하므로, 카드를 사용 중인 다른 앱을 닫으세요.

## 화면이 안 나와요.

본체가 독에 꽂혀 있고 켜져 있는지, HDMI 케이블이 카드의 **입력** 에 꽂혀 있는지, 비디오 패널에서 올바른 카드가 선택되어 있는지 확인하세요. macOS에서는 시스템 설정 → 개인정보 보호 및 보안에서 NS2Bench에 **카메라** 를 허용하세요. 자세한 내용은 **진단** 을 실행하세요.

## 소리가 안 나와요.

상단 바의 **소리 끔** 을 클릭해 소리를 켜세요. macOS에서는 NS2Bench에 **마이크** 를 허용하세요. 같은 캡처 카드가 두 개라면 NS2Bench는 USB 위치로 소리와 화면을 짝짓습니다.

## 캡처는 CPU를 얼마나 쓰나요?

macOS에서는 1080p60에서 코어 하나의 약 12%입니다(하드웨어 JPEG 및 H.264). Linux에서는 MJPEG 카드의 영상을 재인코딩 없이 그대로 전달합니다.

# 입력 장치

## Bridge 표시가 계속 빨간색이에요.

- **Linux 보드:** 보드에 전원이 들어와 있고 설정 → 장치의 주소로 접근 가능한지, 토큰 파일이 보드의 토큰과 일치하는지 확인하세요.
- **Pico:** 시리얼 포트와 보드 레이트가 921600인지 확인하세요. TX와 RX는 교차해야 하며(어댑터 TX → Pico GP1, 어댑터 RX → Pico GP0) GND도 연결해야 합니다.
- **CH9329:** 모듈의 보드 레이트(보통 9600)에 맞추세요.

그런 다음 입력 장치가 본체의 USB 포트에 꽂혀 있고 본체가 깨어 있는지 확인하세요.

## 버튼 입력이 인식되지 않아요.

Switch 2는 한 번의 입력이 최소 약 50 ms 이상 지속되어야 합니다. NS2Bench는 모든 입력을 최소 75 ms 동안 유지합니다. Bridge가 초록색인데 아무 일도 없다면 본체가 절전 모드이거나 화면이 어두워진 상태일 수 있습니다. 첫 입력은 본체를 깨우기만 합니다.

## C, GL, GR은 어떻게 쓰나요?

GL과 GR은 Nintendo Switch 2 Pro 컨트롤러 뒷면의 두 버튼이며, Joy-Con 2에는 없습니다. 이 버튼들(과 C)을 쓰려면 Linux 보드를 사용하고 조작 중 패널에서 **본체 인식 → Pro 컨트롤러** 를 선택하세요. 그러면 본체에 Switch 2 Pro 컨트롤러로 보입니다. 그렇지 않으면 C는 GameChat 단축키로 작동합니다.

## 내 게임패드를 쓸 수 있나요?

네. 컴퓨터에 연결하세요. NS2Bench는 버튼 위치로 매핑합니다(아래쪽 페이스 버튼이 B).

## 키보드로 입력할 수 있나요?

조작 중 패널에서 **키보드 입력 → 키보드와 마우스** 를 선택하세요. 본체에는 진짜 USB 키보드로 보입니다. Linux 보드, 표준 모드의 Pico, 또는 CH9329가 필요합니다.

## 본체가 절전 모드가 되면 어떻게 되나요?

본체 USB로 전원을 받는 보드는 전원이 끊기고 본체가 깨어날 때 다시 시작합니다. NS2Bench는 자동으로 다시 연결합니다. Bridge가 오프라인인 동안의 입력은 버려지며 나중에 재생되지 않습니다.

## NS2Bench가 절전 모드의 본체를 깨울 수 있나요?

네, 약간의 도움이 있으면 됩니다. 어두워진 화면은 아무 버튼이나 누르면 깨어나며, NS2Bench가 알아서 처리합니다. 절전 모드, 충돌, 전원 꺼짐 상태에서는 **설정 → 장치 → 전원 및 깨우기**에서 다음 중 하나를 설정해야 합니다.

- **HDMI-CEC(기계 장치 불필요):** 독과 캡처 카드 사이의 HDMI 케이블에 USB-CEC 어댑터(예: Pulse-Eight)를 연결하면 TV가 보내는 것과 같은 "전원 켜기" 신호를 보냅니다. 본체의 **설정 → TV 출력 → TV 전원 상태에 맞추기**를 켜고, 컴퓨터에 libcec를 설치하세요(Mac에서는 `brew install libcec`). 본체를 절전 모드로 보낼 수도 있습니다.
- **전원 버튼 명령:** SwitchBot 같은 버튼 누르기 장치, Home Assistant 웹훅 또는 릴레이용입니다. 충돌이나 전원 꺼짐 상태에서 되돌릴 수 있는 유일한 방법입니다.

그러면 **본체 깨우기**(화면 없음 화면, 검색, API `POST /api/power`, `power` MCP 도구, `ns2bench power wake`)가 CEC, 허용한 경우 전원 버튼, 그다음 버튼 입력 순으로 시도합니다. Switch 2에는 Wake-on-LAN이 없고, 본체 USB 포트로 전원을 받는 보드는 절전 모드 약 7초 후 꺼집니다. 본체가 깨어나면 보드가 다시 부팅되고, NS2Bench는 약 30초 안에 스스로 다시 연결됩니다.

# 오프라인 본체 네트워크

## 네트워크가 필요한가요?

아니요. 캡처와 USB 입력은 네트워크 없이 작동합니다. 본체 네트워크는 LAN으로 본체와 통신하는 도구를 위한 것입니다.

## 인터넷 없이 본체에 LAN을 주려면?

본체의 이더넷(독 포트 또는 USB 어댑터)을 Mac이나 Linux 컴퓨터의 전용 이더넷 어댑터에 연결하고 `ns2bench-netd`를 실행하세요. 주소를 나눠 주고 연결 테스트에만 응답합니다. 또는 인터넷이 차단된 라우터, VLAN, Wi-Fi 네트워크를 사용하세요. [설정 가이드](docs/setup/README.md#optional-offline-console-network)를 참고하세요.

## 인터넷 차단을 끌 수 있나요?

아니요. 설정 항목이 아닙니다. NS2Bench는 본체 트래픽을 전달하거나 NAT 또는 프록시하지 않으며, 상위 DNS 서버에 질의하지도 않습니다.

## Windows를 쓰고 있어요.

네트워크 서비스는 macOS와 Linux에서 실행됩니다. Windows에서는 본체의 이더넷 포트를 맡는 Linux 보드나 PC에서 실행하고 네트워크 탭에서 제어하거나([원격 도우미](docs/REFERENCE.md#remote-helper-windows-hosts)), 인터넷이 차단된 라우터를 사용하세요.

# 에이전트와 API

## 어떤 에이전트가 작동하나요?

모든 MCP 클라이언트: Claude Code, Codex, opencode 등. 설정 → API 및 MCP에 바로 복사할 수 있는 구성이 있습니다.

## 에이전트를 멈출 수 있나요?

네. 조작 중 패널의 **에이전트 차단(수동 전용)** 은 에이전트 입력을 즉시 멈춥니다. 다시 끌 수 있는 것은 NS2Bench 창에서의 사용자 본인뿐입니다.

## 내 네트워크에서 API는 안전한가요?

엔진은 기본적으로 `127.0.0.1`에서만 수신합니다. 다른 주소에서 수신하려면 토큰이 필요합니다. 다른 사이트의 웹 페이지는 명령을 보낼 수 없습니다.

## API 문서는 어디 있나요?

[docs/REFERENCE.md](docs/REFERENCE.md#agents-mcp-and-http-api)에 있습니다.

# 앱과 업데이트

## 업데이트는 어떻게 이루어지나요?

앱은 매일 GitHub 릴리스를 확인하고 업데이트가 있으면 알려 줍니다. 모든 다운로드는 설치 전에 릴리스의 SHA-256과 대조됩니다. 자동 다운로드와 설치는 기본적으로 꺼져 있으며, 설정 → 업데이트에서 켤 수 있습니다.

## macOS에서 앱이 손상되었거나 확인할 수 없다고 나와요.

앱이 아직 공증되지 않았습니다. `xattr -dr com.apple.quarantine /Applications/NS2Bench.app`을 한 번 실행한 뒤 여세요.

## Windows에서 PC를 보호했다고 나와요.

**추가 정보 → 실행** 을 선택하세요. 설치 프로그램이 아직 유료 인증서로 서명되지 않았습니다.

## 업데이트 후 macOS가 다시 카메라나 마이크 권한을 물어봐요.

0.0.3부터 모든 NS2Bench 빌드가 같은 서명을 가지므로 macOS는 한 번만 묻고, 재시작이나 업데이트 후에도 기억합니다. 0.0.2 이하에서 업데이트하면 마지막으로 한 번 더 묻습니다.

## 테마나 언어는 어떻게 바꾸나요?

설정 → 화면 모드. 상단 바의 달 버튼으로 라이트와 다크를 전환합니다.

## 클립, 스크린샷, 로그는 어디 있나요?

`~/.ns2bench/`에 있습니다. 클립, 테스트 보고서, 그리고 `~/.ns2bench/logs`에 하루 하나씩 로그 파일(7일 보관)이 있습니다. 스크린샷은 다운로드 폴더에 저장됩니다. 어디에도 업로드되지 않습니다.

## NS2Bench가 알림을 보낼 수 있나요?

네. **설정 → 알림** 에서 Bridge나 화면이 끊길 때, 테스트와 클립이 끝날 때, 에이전트가 조작을 시작할 때, 업데이트가 준비됐을 때 데스크톱 알림을 켤 수 있습니다. 기본적으로 NS2Bench가 백그라운드에 있을 때만 표시됩니다.

## 명령줄 도구는 어떻게 설치하나요?

**설정 → 설치 → 명령줄 도구 설치** 를 누르면 `ns2bench`가 PATH에 들어갑니다(macOS는 비밀번호를 한 번 물을 수 있고, Linux `.deb`는 이미 설치합니다). 그다음 `ns2bench --help`를 실행하세요. API와 MCP로 할 수 있는 모든 일을 할 수 있습니다.

# 문제 해결

## 버그는 어떻게 신고하나요?

상단 바의 **도움말** 을 클릭한 다음 **버그 보고서 저장**(로그, 상태, 스크린샷이 담긴 zip, 토큰 제외)을 눌러 [GitHub issue](https://github.com/phantomptr/ns2bench/issues/new/choose)에 첨부하세요.

## 로그 색상은 무슨 뜻인가요?

파란 줄은 정상 활동, 주황 줄은 저절로 해결될 수 있는 경고, 빨간 줄은 직접 조치가 필요한 항목입니다. NS2Bench가 알아보는 문제라면 줄 아래 파란 상자에 무슨 일이 있었고 무엇을 해야 하는지 나옵니다. 로그 패널의 **문제** 는 경고와 오류만 보여 주고, **전체** 는 각 API 호출 같은 세부 정보도 보여 줍니다.

## doctor는 무엇을 하나요?

앱의 **도움말 → 점검 실행**(또는 `ns2bench doctor`)은 비디오, 본체 화면, OCR, Bridge, USB 상태, 보정, 네트워크 격리를 점검하고 어느 부분이 고장 났는지, 무엇을 해야 하는지 알려 줍니다. `--probe`는 HOME 메뉴에서 RIGHT와 LEFT도 눌러 입력을 처음부터 끝까지 테스트합니다.
