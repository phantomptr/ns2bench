# NS2Bench のセットアップ

NS2Bench を使うと、あなた自身や AI エージェントがコンピューターから Nintendo Switch 2 を見て、聞いて、操作できます。
このガイドでは、その配線方法を説明します。

![NS2Bench セットアップの概要](overview.svg)

どのセットアップも、独立した 2 つの部分でできています。

- **目（必須）：** 本体の HDMI を USB キャプチャカードにつなぎます。カードがコンピューターに映像と音声を渡します。
- **手（任意）：** 小さな入力デバイスを本体の USB ポートに挿します。コンピューターがそこへコマンドを送ります。本体からは有線コントローラー、キーボード、マウスに見えます。

人はブラウザーの NS2Bench ページかデスクトップアプリを使います。エージェントは同じコンピューター上の HTTP API または MCP（`127.0.0.1:7630`）を使います。全員が 1 つのベンチを共有し、エージェントの操作はすべてライブで確認できます。

**本体はオフラインのままです。** NS2Bench が本体にインターネット接続を与えることはありません。キャプチャと USB 入力にネットワークはまったく不要です。

## どのセットアップが必要？

| 手元にあるもの | セットアップ | 設定の入力接続 |
|---|---|---|
| キャプチャカードだけ | [表示のみ](#view-only) | 表示のみ |
| USB デバイスモード対応の Linux ボード（Luckfox Pico Pro/Max、Raspberry Pi Zero 2 W、Pi 4/5） | [Linux ボード](#linux-usb-gadget-board) | ネットワーク Bridge |
| Raspberry Pi Pico（RP2040）と 3.3 V の USB-UART アダプター | [Pico](#raspberry-pi-pico) | シリアル Bridge |
| CH9329 モジュール（キーボードとマウスのみ） | [CH9329](#ch9329-module) | CH9329 |
| 本体をローカルネットワークにもつなぎたい（自作ソフトのツール） | [オフラインネットワーク](#optional-offline-console-network) | （ネットワークタブ） |

迷ったら、まず **表示のみ** から始めて、あとで入力デバイスを追加しましょう。入力設定はアプリを再起動せずに変更できます。

C、GL、GR を含むすべてのコントローラーボタンを使いたいなら、Linux ボードを使ってください。その **Pro** モードでは、本体から Switch 2 Proコントローラーに見えます。Pico とボードの標準モードは、C、GL、GR 以外のすべてのボタンに対応しています。CH9329 にはコントローラー機能がまったくありません。

## はじめる前に：コンピューターの準備

[最新リリース](https://github.com/phantomptr/ns2bench/releases/latest) からアプリをインストールし、次の手順に進みます。

### macOS（14 以降）

- **追加でインストールするものはありません。** キャプチャ、音声、画面上の文字の読み取りはアプリに組み込まれています。
- 初回起動：macOS が「アプリが壊れている」または「確認できない」と表示した場合は、`xattr -dr com.apple.quarantine /Applications/NS2Bench.app` を一度実行してください。
- 確認が出たら **カメラ**（映像）、**マイク**（本体の音声）、**ローカルネットワーク**（入力デバイス）を許可してください。あとからシステム設定 → プライバシーとセキュリティで変更できます。
- **クリップ**（クリップを保存）には ffmpeg が必要です：`brew install ffmpeg`。
- シリアルアダプター（Pico、CH9329）はドライバーなしで動き、`/dev/cu.usbserial-…` や `/dev/cu.usbmodem…` として表示されます。

### Windows 10/11

- **ffmpeg をインストール**（キャプチャ、音声、クリップで使います）：`winget install Gyan.FFmpeg` を実行し、NS2Bench を再起動します。Chocolatey や Scoop でインストールした ffmpeg や、`ns2bench-app.exe` と同じ場所にある `ffmpeg.exe` も NS2Bench が見つけます。
- SmartScreen が「Windows によって PC が保護されました」と表示した場合は、**詳細情報 → 実行** を選んでください。
- USB-UART アダプターにはメーカーのドライバー（CH340/CH341 または CP210x）が必要な場合があります。ポートはデバイス マネージャーで `COM3` などとして表示されます。
- 任意：画面上の文字の読み取りには [Tesseract](https://github.com/UB-Mannheim/tesseract/wiki)。
- オフラインの本体ネットワークサービスは Windows では動きません。[Linux ヘルパーかルーター](#optional-offline-console-network) を使ってください。

### Linux

- **ffmpeg：** `.deb` なら自動でインストールされます。AppImage の場合は自分でインストールしてください（`sudo apt install ffmpeg`、`sudo dnf install ffmpeg`、`sudo pacman -S ffmpeg`）。
- **権限：** キャプチャカードとシリアルポートを所有するグループに自分を追加し、ログアウトしてログインし直します：
  `sudo usermod -aG video,dialout $USER`（Arch：`video,uucp`）。
- AppImage：`chmod +x NS2Bench-*.AppImage`。起動しない場合は FUSE 2 をインストールしてください（`sudo apt install libfuse2`）。
- 任意：画面上の文字の読み取りには `sudo apt install tesseract-ocr`。
- シリアルポートは `/dev/ttyACM0`（Pico）または `/dev/ttyUSB0`（ほとんどのアダプター）として表示されます。

## キャプチャカード（すべてのセットアップ共通）

- USB **UVC** の HDMI キャプチャカードならどれでも使えます。目標は 1080p60 です。動作確認済み：UGREEN 15389（MS2130）。
- 本体ドックの **HDMI 出力** をカードの HDMI 入力につなぎます。カードは USB でコンピューターにつなぎます。
- **ビデオ** パネルでカード、解像度、フレームレート、画質を選びます。カードが対応しているものだけが表示されます。
- **音声** もキャプチャカードから届きます。別の音声ケーブルはありません。
- **macOS：** 小さな内蔵ヘルパーがキャプチャを行います。カードは OBS と共有されます。OBS がすでにカードを使っている場合、NS2Bench は OBS のフォーマットを使い、カードを奪うことはありません。初回起動時に **カメラ**（映像）、**マイク**（本体の音声）、**ローカルネットワーク**（Bridge）を許可してください。
- **Linux と Windows：** NS2Bench は `ffmpeg` を使います（先にインストールしてください）。カードが空いている必要がある場合があるので、映像が出ないときは OBS などカードを使っているアプリを閉じてください。
- `ns2bench devices` を実行すると、NS2Bench が認識しているキャプチャカードの一覧が表示されます。

## 表示のみ

![表示のみ：キャプチャカードだけで入力デバイスなし](view-only.svg)

いちばんシンプルなベンチです。ライブで見る、録画する、フル解像度のスクリーンショットを撮る、画面上の文字を読み取る（OCR）ことができます。エージェントも見ることはできますが、誰もボタンは押せません。

**用意するもの**

- ドックに入れた本体
- USB HDMI キャプチャカード（UVC）
- HDMI ケーブルとカードの USB ケーブル

**手順**

1. ドックの HDMI 出力をキャプチャカードにつなぎます。
2. キャプチャカードをコンピューターに挿します。
3. NS2Bench を起動し、`http://127.0.0.1:7630` を開きます（またはデスクトップアプリ）。
4. **ビデオ** パネルでカードを選びます。
5. **設定 → デバイス** で **入力接続** を **表示のみ** にして、**入力接続を適用** をクリックします。

**動作の確認**

- 上部バーの **ビデオ** ピルが緑になり、本体の映像が表示されます。
- **Bridge** ピルには *not configured* と表示されます。ここではそれで正常です。

**よくある問題**

- *映像が真っ黒：* 本体をスリープから復帰させ、ドックに入っていてドックに電源が来ていることを確認します。別の HDMI ケーブルも試してください。
- *カードが一覧に出ない：* macOS ではカメラへのアクセスを許可します。Linux や Windows では、カードを使っているアプリを閉じてください。
- *音が出ない：* macOS ではマイクへのアクセスを許可します。カードが音声ソースとして選ばれているか確認してください。

## Linux USB ガジェットボード

![Linux ボード：本体へ USB、コンピューターへ Ethernet](input-linux-board.svg)

小さな Linux ボードが USB デバイスのふりをします。ボード上では **NS2Bench Bridge**（`ns2bench-board`）が動きます。これは動作確認済みのセットアップです（Luckfox Pico Pro/Max）。2 つのコントローラーモードに対応しています。

- **標準**（既定）：本体からは HORI 風の有線コントローラー + USB キーボード + USB マウスに見えます。
- **Pro**：本体からは Switch 2 Proコントローラーに見え、C、GL、GR を含むすべてのボタンが使えます。このモードではキーボードとマウスは使えません。

モードは操作パネルの **本体での認識** で切り替えます。約 8 秒かかります。

**用意するもの**

- USB デバイス（OTG）モード対応の Linux ボード：Luckfox Pico Pro/Max、Raspberry Pi Zero 2 W、または USB-C ポートを使う Pi 4/5
- ボードの **OTG** ポートからドックの USB ポートへの USB ケーブル
- コンピューターへの Ethernet ケーブル（または Wi-Fi やボードの USB ネットワーク）
- 上記のキャプチャカードのセットアップ

**手順**

1. コンピューターからボードに NS2Bench Bridge をインストールします：`make board-install BOARD=<ssh-host>`。64 ビットの Raspberry Pi では `BOARD_TARGET=aarch64-unknown-linux-musl` を追加します。
2. ボードの **OTG** USB ポートをドックの USB ポートにつなぎます。
3. ボードの Ethernet をコンピューターにつなぎます（または両方を同じプライベートネットワークに参加させます）。
4. Bridge がまだ動いていなければ起動します：`ssh <ssh-host> /opt/ns2bench/ns2bench-hidd.sh start --bind <board-ip>`。
5. コンピューター上のトークンファイル `~/.ns2bench/hidd.token` がボードのトークンと一致していることを確認します。
6. **設定 → デバイス** で次のように設定します：
   - **入力接続：** ネットワーク Bridge
   - **Bridge アドレス：** ボードの IP（既定は `192.168.79.2`）
   - **Bridge ポート：** `7631`
   - **Bridge トークンファイル：** `~/.ns2bench/hidd.token`
7. **入力接続を適用** をクリックします。

**動作の確認**

- **Bridge** ピルが緑になり、往復時間と *usb configured* が表示されます。
- 画面上の Joy-Con のボタンを押します。本体が反応し、ボタンが光ります。

**本体がスリープしたとき**

本体の USB から給電しているボードは、本体がスリープすると電源が切れ、復帰すると再び起動します。NS2Bench は起動したままにしておいてください。約 3 秒以内に気づいて自動で再接続します。ボードの起動が終わり、本体が USB の準備を終えると、入力が再び使えるようになります。

そのためには、ボードが起動時に自分で立ち上がる必要があります。`/opt/ns2bench/gadget.sh` を実行し、続いて `/opt/ns2bench/ns2bench-hidd.sh start` を実行する起動スクリプトをボードに追加してください。お使いのボードとドックで、実際のスリープと復帰を一度試してください。

**よくある問題**

- *Bridge offline · reconnecting：* ケーブルとボードの IP を確認します。ボードに ping を送ります。ボード上で Bridge が動いているか確認してください。
- *Bridge はつながっているが usb が configured にならない：* 本体をスリープから復帰させます。ケーブルが給電専用ポートではなくボードの **OTG** ポートにつながっているか確認してください。給電しかできないケーブルもあります。
- *HOME メニューでマウスが反応しない：* 正常です。本体はマウスを読み取っていますが、カーソルを表示するのは一部のソフトだけです。
- *キーボードが無視される：* 本体の USB キーボード対応は、設定 → コントローラーとアクセサリーにあります。
- ボード上での停止や起動は、必ず `ns2bench-hidd.sh` と `gadget.sh` で行ってください。パターン指定でプロセスを kill しないでください。

## Raspberry Pi Pico

![Raspberry Pi Pico：本体へ USB、コンピューター側の USB アダプターへ UART](input-pico.svg)

NS2Bench Bridge ファームウェアを動かす Raspberry Pi Pico（RP2040）です。USB ポートは本体につながり、標準モードの Linux ボードと同じコントローラー + キーボード + マウスとして見えます。コンピューターとは、別の USB-UART アダプターを介したシリアル（UART）接続で通信します。

> Pico ファームウェアはビルドできていますが、まだ実機では動かしていません。報告を歓迎します。

**用意するもの**

- Raspberry Pi Pico（RP2040）と micro-USB ケーブル
- **3.3 V** の USB-UART アダプター（CP2102、FT232 または CH340）
- ジャンパーワイヤー 3 本
- 上記のキャプチャカードのセットアップ

**手順**

1. ファームウェアをビルドします：`make pico`。`firmware/pico/ns2bench-pico.uf2` ができます。
2. **BOOTSEL** ボタンを押したまま、Pico を **コンピューター** に挿します。**RPI-RP2** というドライブが表示されます。
3. `.uf2` ファイルをそのドライブにコピーします。Pico が再起動します。抜いてください。
4. Pico とアダプターを配線します：
   - Pico **GP0**（ピン 1、UART0 TX）→ アダプター **RX**
   - Pico **GP1**（ピン 2、UART0 RX）← アダプター **TX**
   - Pico **GND**（ピン 3）— アダプター **GND**
   - アダプターの 3.3 V / 5 V ピンはつながないでください。Pico は本体から給電されます。
5. Pico の micro-USB をドックの USB ポートに挿します。
6. アダプターをコンピューターに挿します。
7. **設定 → デバイス** で次のように設定します：
   - **入力接続：** シリアル Bridge
   - **シリアルポート：** アダプター（例：macOS では `/dev/cu.usbserial-XXXX`、Linux では `/dev/ttyUSB0`、Windows では `COM3`）
   - **ボーレート：** `921600`
8. **入力接続を適用** をクリックします。

任意：`NS2BENCH_TOKEN=... make pico` でビルドすると、Pico がトークンを要求するようになります（コンピューターにも同じトークンファイルを設定します）。アダプターが 921600 に対応していない場合は `NS2BENCH_BAUD=115200` でビルドしてください。

**動作の確認**

- **Bridge** ピルが緑になり、*usb configured* と表示されます。
- 画面上の Joy-Con を押すと本体に届きます。

**よくある問題**

- *シリアルポートが表示されない：* アダプターのドライバー（CP210x、FTDI または CH340）をインストールし、挿し直してください。
- *Bridge offline：* TX と RX が逆になっている可能性が高いです。TX は必ず RX につなぎます。GND も確認してください。
- *応答が文字化けする、または返ってこない：* ボーレートはファームウェアと一致している必要があります（別の値でビルドしていなければ 921600）。
- *5 V のアダプターは絶対に使わないでください。* Pico のピンは 3.3 V 専用です。

## CH9329 モジュール

![CH9329：本体へ USB、コンピューターへ UART](input-ch9329.svg)

CH9329 モジュールは、シリアルコマンドを USB キーボードとマウスの操作に変換します。安くてシンプルですが、**コントローラー機能はありません**。ボタンもスティックもありません。文字入力とポインター操作専用に使ってください。

**用意するもの**

- CH9329 モジュール
- 3.3 V の USB-UART アダプター（モジュールのケーブルに USB シリアルが内蔵されていない場合）
- 上記のキャプチャカードのセットアップ

**手順**

1. モジュールの USB（HID）側をドックの USB ポートに挿します。
2. UART 側をアダプターに配線します：モジュール TX → アダプター RX、モジュール RX ← アダプター TX、GND — GND。（モジュールに USB シリアルが内蔵されている場合は不要です。）
3. アダプター（またはモジュールのシリアルケーブル）をコンピューターに挿します。
4. **設定 → デバイス** で次のように設定します：
   - **入力接続：** CH9329
   - **シリアルポート：** アダプターのポート
   - **ボーレート：** モジュールの設定値、通常は `9600`
5. **入力接続を適用** をクリックします。

**動作の確認**

- **Bridge** ピルが緑になります。
- ネイティブキーボードモードで入力した文字が本体に表示されます（例：テキスト入力欄）。

**よくある問題**

- *コントローラーのボタンが反応しない：* 想定どおりです。CH9329 はキーボードとマウス専用です。
- *何も起きない：* ボーレートを確認し、必要なら TX/RX を入れ替えてください。
- *本体がキーボードを無視する：* 設定 → コントローラーとアクセサリー → USB キーボードを確認してください。

## 任意：オフラインの本体ネットワーク

![本体にオフラインネットワークを用意する 3 つの方法](network.svg)

これが必要なのは、自作ソフトのローダーなどローカルネットワークのツールを使う場合だけです。キャプチャと入力には一切不要です。

どの方法を選んでも、本体は **インターネットにつながりません**。NS2Bench はトラフィックを転送せず、インターネット共有、NAT、プロキシを有効にせず、外部の DNS サーバーに問い合わせることもありません。ローカルの DNS は本体の接続テストにだけ応答し、それ以外の名前はすべて拒否します。本体が試みた名前解決はすべて **ネットワーク** ログに表示されます。

コンピューターから Linux ボードへの Bridge 接続はこれとは別です。普段の LAN を使ってかまいません。

### A · 直接ケーブル接続（macOS または Linux）

**用意するもの：** コンピューター側に本体専用の予備の Ethernet アダプター、Ethernet ケーブル、ドックの LAN ポート（または本体側の USB-Ethernet アダプター）。

1. 専用アダプターに固定のプライベートアドレスを設定します（例：`192.168.80.1/24`）。NS2Bench はインターフェースを設定しません。
2. そのインターフェースを `bench.json` に記述します（お使いのアダプターのインターフェース名を使ってください）：
   ```json
   "network": { "interface": "en7", "address": "192.168.80.1", "subnet": "192.168.80.0/24",
                "pool_start": "192.168.80.10", "pool_end": "192.168.80.13" }
   ```
   ネットワークサービスをビルドします：`make netd`。
3. ポートを開かずに設定を確認します：`native/target/release/ns2bench-netd --check bench.json`。
4. サービスとしてインストールします：
   - **macOS：** バイナリを `~/.ns2bench/bin/ns2bench-netd` にコピーし、`launchd/ns2bench-netd.plist.template` を埋めて `~/Library/LaunchAgents/` にコピーします。root は不要です。
   - **Linux：** `/opt/ns2bench/ns2bench-netd` にインストールし、systemd ユニット `launchd/ns2bench-netd.service` を使います。
5. 本体の Ethernet を専用アダプターにつなぎます。
6. **設定 → ネットワーク** で **直接接続・隔離されたコンピューター ↔ 本体** を選びます。必要に応じてローカルの DHCP、DNS、接続テストページをオンにして適用します。

本体はプールからアドレスを受け取ります（例：`192.168.80.10`–`192.168.80.13`）。**ネットワーク** タブにライブの状態とリースが表示されます。

IP フォワーディングがオンの場合や、それを確認できない場合、サービスは起動を拒否します。これは意図的な動作です。

### B · 隔離されたルーター、VLAN または Wi-Fi（どの OS でも）

1. 本体用に、**IPv6 も含めてインターネットを遮断した** ルーター、VLAN または Wi-Fi ネットワークを用意します。普通の家庭用 LAN は隔離されていません。
2. アドレスの割り当て（DHCP）はルーターに任せます。
3. 本体を Ethernet または Wi-Fi でそこにつなぎます。
4. **設定 → ネットワーク** で **隔離されたルーター / VLAN / Wi-Fi** を選びます。これで NS2Bench のローカル DHCP と DNS がオフになり、ルーターとぶつかりません。

### C · リモートヘルパーを使う Windows コンピューター

Windows ではネットワークサービスをローカルで動かせません。代わりに Linux ボードや PC で動かし、Windows から操作します。

1. Linux ヘルパーで、方法 A と同じように `ns2bench-netd` を設定します。本体の Ethernet はヘルパーが受け持ちます。
2. トークンを作ります：`openssl rand -hex 16 > ~/.ns2bench/netd-control.token`。同じファイルを Windows コンピューターにコピーします。
3. ヘルパーの設定に、本体のネットワーク **ではない** プライベートアドレスで管理用リスナーを追加します：
   ```json
   "network": { "control": { "listen": "192.168.79.1:7632", "token_file": "~/.ns2bench/netd-control.token" } }
   ```
4. Windows 側の NS2Bench の設定で、ヘルパーを指定します：
   ```json
   "network": { "helper": { "url": "http://192.168.79.1:7632", "token_file": "~/.ns2bench/netd-control.token" } }
   ```
5. 管理用の接続はプライベートに保ってください（直接ケーブルかボードの USB ネットワーク）。通信は暗号化されていない HTTP です。

これで Windows の **ネットワーク** タブに、ヘルパーの状態と操作項目が表示されます。ヘルパーを使わず、方法 B を選んでもかまいません。

**よくある問題**

- *ネットワークタブに利用不可と表示される：* サービスが動いていないか、サービスと UI が別の状態フォルダーを使っています。Windows では `network.helper` と、両方のトークンファイルが一致しているかを確認してください。
- *本体にアドレスが割り当てられない：* 設定のインターフェース名とサブネット、ケーブルが専用アダプターにつながっているかを確認してください。
- *本体がインターネットにつながっていないと表示する：* それで正しい状態です。接続テストはローカルで成功しますが、その先には何も出ていきません。

## エージェント

ピルが緑になれば、エージェントがベンチを使えます。**設定 → API と MCP** を開くと、API アドレス、リクエスト例、Claude Code・Codex・opencode 向けのコピーしてすぐ使える MCP 設定があります。エージェントと人は同じ操作を共有し、手動専用スイッチでいつでもエージェントの入力をブロックできます。

## Windows についての補足

- キャプチャは DirectShow 経由で `ffmpeg` を使います。カードを使っている他のアプリは閉じてください。
- Linux ボード、Pico、CH9329 はどれも Windows から使えます。シリアルポートの名前は `COM3`、`COM4` などです。
- Windows にはローカルのネットワークサービスがありません。リモートヘルパー（方法 C）か隔離されたルーター（方法 B）を使ってください。
