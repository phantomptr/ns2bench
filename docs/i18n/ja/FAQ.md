# 全般

## NS2Bench とは？

机の上の Nintendo Switch 2 のためのベンチです。本体の映像と音をパソコンに表示し、あなたや AI エージェントがボタンを押せるようにします。クリップの録画、画面上の文字の読み取り、繰り返し可能なテストができます。

## 誰のためのもの？

実機でソフトウェアをテストする開発者、繰り返しのチェックを自動化したい人、アクセシビリティの実験をする人、そして AI エージェントに本体を操作させてそれを見ていたいすべての人です。

## 本体を改造しますか？

いいえ。NS2Bench はテレビと有線コントローラーがすることしかしません。HDMI を受け取り、USB でボタンを押すだけです。本体には何もインストールされません。

## 本体はインターネットにつながりますか？

いいえ。NS2Bench は本体にインターネットアクセスを与えません。キャプチャと USB 入力にはネットワークは一切不要です。オプションの本体用ネットワークは本体の接続テストに応答するだけで、通信を転送することはありません。[オフラインの本体ネットワーク](#offline-console-network)を参照してください。

## 無料ですか？

はい。NS2Bench は GPL-3.0 ライセンスの無料オープンソースです。自由に使用・変更・共有できます。配布するときは変更の有無にかかわらず「NS2Bench, created by PhantomPtr」の表記とライセンスを残してください。変更版を配布する場合は、受け取る人にソースコードを提供し、変更版であることを明示してください（NOTICE を参照）。役に立ったら[サポート](README.md#support)していただけます。

## 任天堂と関係がありますか？

いいえ。NS2Bench は独立したプロジェクトです。Nintendo Switch は任天堂の商標です。

# セットアップ

## 何が必要ですか？

映像と音のためのキャプチャカード（必須）、そしてボタンを押したい場合は入力デバイスが 1 つ必要です。

- USB デバイスポートのある Linux ボード（Luckfox Pico Pro/Max、Raspberry Pi Zero 2 W、Pi 4/5）
- または Raspberry Pi Pico と 3.3 V の USB-UART アダプター
- または CH9329 モジュール（キーボードとマウスのみ）

[セットアップガイド](docs/setup/README.md)に、それぞれの配線図と手順があります。

## パソコンに何をインストールすればいいですか？

- **macOS:** 不要です。カメラ、マイク、ローカルネットワークを許可するだけです。クリップを保存したい場合は `brew install ffmpeg`。
- **Windows:** ffmpeg（`winget install Gyan.FFmpeg`）と、シリアルアダプターが必要とする場合は CH340/CP210x ドライバー。
- **Linux:** ffmpeg（`.deb` が自動でインストールします）と `video`・`dialout` グループ（`sudo usermod -aG video,dialout $USER`）。

[始める前に](docs/setup/README.md#before-you-start-your-computer)を参照してください。

## どの入力デバイスを選べばいいですか？

C、GL、GR を含むすべてのボタンを使いたいなら Linux ボードを使ってください。Pro モードでは本体に本物の Switch 2 Proコントローラーとして見えます。Pico は最も安いコントローラーの選択肢です（C、GL、GR 以外のすべてのボタン）。CH9329 はキーボードとマウスのみです。まず表示だけで始めて、あとから入力デバイスを追加することもできます。

## ドックは必要ですか？

本体から HDMI を出力する手段が必要で、通常はドックを使います。入力デバイスはドックの USB ポートの 1 つに挿します。

## 入力デバイスなしで使えますか？

はい。設定 → デバイス で **表示のみ（入力デバイスなし）** を選んでください。映像を見る、音を聞く、スクリーンショットを撮る、クリップを保存する、画面上の文字を読むことができます。

## キャプチャカードはどこで設定しますか？

メインウィンドウ右側の **ビデオ** パネルです。お使いのカードが対応するフォーマットだけが表示されます。

## 入力デバイスはどこで設定しますか？

**設定 → デバイス** です。変更は再起動なしで反映され、古い接続は先にすべてのボタンを離します。

## 動作しているかどうかはどうやって分かりますか？

上部バーの **ビデオ** ピルがフレームレートとともに緑になり、本体が入力デバイスを受け入れると **Bridge** ピルが緑になります。上部バーの **診断** で状態の概要をまとめてコピーできます。

# キャプチャとサウンド

## どのキャプチャカードが使えますか？

USB（UVC）の HDMI キャプチャカードならどれでも使えます。目標は 1080p60 です。テスト済み: UGREEN 15389（MS2130）、1080p60 と 1440p30。

## OBS と同時に使えますか？

macOS では使えます。NS2Bench は OBS とカードを共有し、取り上げることはありません。Windows と Linux では ffmpeg が通常カードを専有するので、カードを使っているほかのアプリを閉じてください。

## 映像が映らない。

本体がドックに入っていて電源が入っていること、HDMI ケーブルがカードの **入力** に挿さっていること、ビデオパネルで正しいカードが選ばれていることを確認してください。macOS では、システム設定 → プライバシーとセキュリティ で NS2Bench に **カメラ** を許可してください。詳しくは **診断** を実行してください。

## 音が出ない。

上部バーの **サウンドオフ** をクリックして音をオンにしてください。macOS では NS2Bench に **マイク** を許可してください。同じキャプチャカードが 2 枚ある場合、NS2Bench は USB の位置で音と映像を組み合わせます。

## キャプチャの CPU 使用率はどのくらい？

macOS では 1080p60 で 1 コアの約 12% です（ハードウェア JPEG と H.264）。Linux では MJPEG カードの映像を再エンコードせずにそのまま渡します。

# 入力デバイス

## Bridge ピルが赤のまま。

- **Linux ボード:** ボードに電源が入っていて、設定 → デバイス のアドレスで到達できること、トークンファイルがボードのトークンと一致していることを確認してください。
- **Pico:** シリアルポートと、ボーレートが 921600 であることを確認してください。TX と RX はクロス接続（アダプター TX → Pico GP1、アダプター RX → Pico GP0）で、GND も接続が必要です。
- **CH9329:** モジュールのボーレート（通常 9600）に合わせてください。

そのうえで、入力デバイスが本体の USB ポートに挿さっていて、本体がスリープしていないことを確認してください。

## 押しても反応しない。

Switch 2 では、1 回の押下が約 50 ms 以上続く必要があります。NS2Bench はすべての押下を 75 ms 以上保持します。Bridge が緑なのに何も起きない場合、本体がスリープ中か画面が暗くなっている可能性があります。最初の押下はスリープ解除だけに使われます。

## C、GL、GR を使うには？

GL と GR は Nintendo Switch 2 Proコントローラーの背面にある 2 つのボタンで、Joy-Con 2 にはありません。これら（と C）を使うには、Linux ボードを使い、操作中パネルで **本体での認識 → Proコントローラー** を選んでください。本体からは Switch 2 Proコントローラーとして見えます。それ以外の場合、C は GameChat のショートカットとして働きます。

## 自分のゲームパッドは使えますか？

はい。パソコンに接続してください。NS2Bench はボタンの位置で割り当てます（下側のフェイスボタンが B）。

## キーボードで文字を入力できますか？

操作中パネルで **キーボードの送信先 → キーボードとマウス** を選んでください。本体には本物の USB キーボードとして見えます。Linux ボード、標準モードの Pico、または CH9329 が必要です。

## 本体がスリープするとどうなりますか？

本体の USB から給電しているボードは電源が切れ、本体の復帰時に再起動します。NS2Bench は自動で再接続します。Bridge がオフラインの間の押下は破棄され、あとから再送されることはありません。

## NS2Bench で本体をスリープから復帰させられますか？

まだできません。Switch 2 には Wake-on-LAN がなく、本体の USB ポートから給電しているボードは本体と一緒に電源が切れます（テスト結果: スリープモードの約 7 秒後に Bridge が切断。本体を復帰させるとボードが起動し、NS2Bench が自動で再接続して約 30 秒以内に使えるようになります）。検討中の方法は 2 つです。ボードに別途給電して起きたままにする方法（本体側へ電力を逆流させない USB 電源分岐ケーブルを使用）と、HDMI-CEC の「テレビの電源状態に合わせる」で HDMI 側の CEC デバイスから本体を起こす方法です。それまでは本体の電源ボタンで復帰させてください。 本体を起動すると、ボードが自動で起動し、NS2Bench は約 30 秒以内に自動で再接続します。

# オフラインの本体ネットワーク

## ネットワークは必要ですか？

いいえ。キャプチャと USB 入力はネットワークなしで動きます。本体用ネットワークは、LAN 経由で本体と通信するツールのためだけのものです。

## インターネットなしの LAN を本体に用意するには？

本体の有線 LAN（ドックのポートまたは USB アダプター）を、Mac または Linux パソコンの専用の有線 LAN アダプターにつなぎ、`ns2bench-netd` を実行してください。アドレスを割り当て、接続テストにだけ応答します。または、インターネットを遮断したルーター、VLAN、Wi-Fi ネットワークを使ってください。[セットアップガイド](docs/setup/README.md#optional-offline-console-network)を参照してください。

## インターネットの遮断をオフにできますか？

いいえ。これは設定項目ではありません。NS2Bench は本体の通信を転送・NAT・プロキシすることはなく、上流の DNS サーバーに問い合わせることもありません。

## Windows を使っています。

ネットワークサービスは macOS と Linux で動作します。Windows では、本体の有線 LAN ポートを受け持つ Linux ボードまたは PC で実行し、ネットワークタブから操作するか（[リモートヘルパー](docs/REFERENCE.md#remote-helper-windows-hosts)）、インターネットを遮断したルーターを使ってください。

# エージェントと API

## どのエージェントが使えますか？

MCP クライアントならどれでも使えます。Claude Code、Codex、opencode などです。設定 → API と MCP にコピーしてすぐ使える設定があります。

## エージェントを止められますか？

はい。操作中パネルの **エージェントをブロック（手動のみ）** でエージェントの入力をすぐに止められます。解除できるのは NS2Bench のウィンドウからのあなただけです。

## API はネットワーク上で安全ですか？

エンジンはデフォルトで `127.0.0.1` だけで待ち受けます。ほかのアドレスで待ち受けるにはトークンが必要です。ほかのサイトの Web ページからはコマンドを送れません。

## API のドキュメントはどこにありますか？

[docs/REFERENCE.md](docs/REFERENCE.md#agents-mcp-and-http-api) にあります。

# アプリとアップデート

## アップデートはどのように行われますか？

アプリは毎日 GitHub のリリースを確認し、アップデートがあれば知らせます。ダウンロードしたファイルはすべて、インストール前にリリースの SHA-256 と照合されます。自動ダウンロードと自動インストールはデフォルトでオフです。設定 → アップデート でオンにできます。

## macOS でアプリが壊れている、または確認できないと表示される。

アプリはまだ公証されていません。`xattr -dr com.apple.quarantine /Applications/NS2Bench.app` を一度実行してから開いてください。

## Windows で PC を保護したと表示される。

**詳細情報 → 実行** を選んでください。インストーラーはまだ有料の証明書で署名されていません。

## アップデート後に macOS がまたカメラやマイクの許可を求める。

アプリが公証されるまでは、macOS はアップデートのたびに新しいアプリとして扱うため、再度確認されることがあります。もう一度許可してください。ほかは何も変わりません。

## テーマや言語を変えるには？

設定 → 外観 です。上部バーの月のボタンでライトとダークを切り替えられます。

## クリップ、スクリーンショット、ログはどこにありますか？

`~/.ns2bench/`（クリップ、レポート、ログ）にあります。どこにもアップロードされません。

# トラブルシューティング

## バグを報告するには？

上部バーの **バンドル** をクリックしてバグレポートの zip（ログ、状態、スクリーンショット 1 枚。トークンは含みません）を保存し、[GitHub issue](https://github.com/phantomptr/ns2bench/issues/new/choose) に添付してください。

## doctor は何をしますか？

`ns2bench doctor` はビデオ、本体の映像、OCR、Bridge、USB の状態、キャリブレーション、ネットワークの隔離をチェックし、どこが壊れていて何をすればよいかを教えてくれます。`--probe` を付けると、HOMEメニューで RIGHT と LEFT を押して入力をエンドツーエンドでテストします。
