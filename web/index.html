          Settings

          NS2Bench Bridge

          Capture and input are independent. Select your capture card in the Video panel; select how this computer reaches your input device here.

          Calibrate presses

          The Switch 2 ignores presses that are too short, and the right length depends on your setup. Go to the HOME menu, then click Calibrate: NS2Bench presses Right and Left a few times, watches the screen and saves the shortest press that always works.

          Power and wake

          A dimmed screen wakes with any press. From Sleep Mode, a crash or power-off, the console needs one of these. Agents and tests can then wake it too.

          Runs on this computer to press the console’s power button: a SwitchBot or other button presser, a Home Assistant webhook, a relay. It is the only way back from a crash or power-off. Only you can set it here; agents can only ask for a press.

          What you need

          Open the setup guide for every way to connect: Linux board, Raspberry Pi Pico, CH9329, view only, and the offline console network.

          Console HDMI → capture card → computer for video. An input device connects by USB to the console and by network or serial to this computer. A Linux device needs USB gadget support; the Pico uses a separate USB-to-UART adapter at 921600 baud. CH9329 cannot send controller buttons.

          Bridge management can use the computer’s existing LAN. The console’s network is configured separately and must stay isolated from the internet.

          Console network

          Checking local network service…

          Internet blocking stays on. Other DNS names are refused; no upstream DNS, forwarding, internet sharing, NAT or proxy is enabled.

          Start a new session in your agent to load it. Keep NS2Bench open while the agent works: the MCP server is part of its engine.

          This engine asks for an API token. Agents need the same token as an Authorization: Bearer header: set it in your agent’s MCP settings after adding the address.

          Keeping it up to date

          Nothing to redo after an update: the address stays the same and the agent gets the new tools the next time it starts. If you change the engine’s port, click Add again so the agent has the new address.

          While an agent works

          You see every press on the on-screen Joy-Con and in the input log. Block agents in the Driving card stops it at once, and only you can turn it back on.

          Another MCP client

          Clients that start the server themselves (stdio) can use this configuration. Keep the paths valid on that computer.

            Common problems
            
      
            There’s no picture
            Check the HDMI cable goes into the capture card’s input, the console is docked and awake, and the card is picked in the Video panel. Close OBS if it holds the card. On a Mac, allow Camera for NS2Bench. More in the FAQ
            
      
            There’s no sound
            Turn on Sound in the toolbar. The sound comes from the capture card, so pick the same card in the Video panel. On a Mac, allow Microphone for NS2Bench. More in the FAQ
            
      
            The Bridge pill stays red
            The Bridge board powers from the console’s USB port, so the console must be awake. Check its cables and its address in Settings → Devices. More in the FAQ
            
      
            Presses don’t register
            The Switch 2 ignores very short presses. Run Calibrate in Settings → Devices, and check Block agents is off if an agent is driving. More in the FAQ
            
      
            macOS keeps asking for permission
            Allow Camera and Microphone once. Since 0.0.3 the app keeps the same signature, so macOS remembers across updates. More in the FAQ
            
      
            Which input device should I pick?
            The NS2Bench Bridge (a Linux board) does everything. A Pico is cheaper and simpler. A CH9329 only types and moves a mouse. More in the FAQ
            
    
            
    
            
      
            Report a problem
            
      
            Save a bug report, then open an issue and attach it (or send it on Discord). The report holds what NS2Bench sees (capture cards, sound devices, serial ports, the network helper), the check, recent logs, startup traces, crash reports, a screenshot and your settings, never tokens. Look through it before you share it.
            
      
            
      
            
      
            NS2Bench closes as soon as it opens
        
            Make a report without the window, from Terminal (macOS, Linux) or Command Prompt (Windows):
            
        
            ns2bench report
            
        
            If the ns2bench command isn’t installed, use the app itself:
            
        
            macOS    /Applications/NS2Bench.app/Contents/MacOS/ns2bench-app report
Windows  "%LOCALAPPDATA%\NS2Bench\ns2bench-app.exe" report
Linux    ./NS2Bench-*.AppImage report
            
        
            The report is saved to your Downloads folder. To start NS2Bench without capture, input or sound (when a device makes it crash), add --safe instead of report.
            
        
            Logs and crash reports are in the logs folder: ~/.ns2bench/logs (Windows: %USERPROFILE%\.ns2bench\logs).

            App updates
            Checking desktop updater…
            
    
            
    
    
    
    
    
            NS2Bench finds a new version by itself, downloads it in the background, and installs it when you quit NS2Bench (Quit in its menu or tray icon), or right away with Restart now. Every update comes from NS2Bench’s GitHub releases and is checked (SHA-256, and on macOS NS2Bench’s signature) before it installs. macOS apps, the Windows setup and Linux AppImages update themselves; a Linux .deb shows where to download the new one.
